K-Closing Alpha

장마감 동시호가 정보로 종목을 골라 종가에 사고 시초가에 파는 퀀트 시스템

개요

국내 주식의 장마감 동시호가(15:20~15:30) 구간에서, 15:20에 볼 수 있는 정보만으로 종목 점수를 매기고 상위 3종목을 종가에 사서 다음 날 시초가에 파는 전략을 연구하고 자동 실행하는 프로젝트입니다. 수익률을 올리는 것보다 "어디서 숫자가 부풀려질 수 있는지"를 먼저 막는 데 집중했습니다. 미래 정보 차단, 거래 비용 반영, 검증 방식, 중복 주문 방지를 각각 코드로 고정했습니다.

CASE 01K-Closing Alpha개인

15:20 판단 시점과 15:30 확정 종가를 컬럼부터 분리해 미래 정보 누출을 막았다

  1. 15:20 수집결정_종가 저장
  2. 점수 산정15:20 정보만 사용
  3. 15:30 확정종가는 별도 컬럼
  4. 종가 매수상위 3종목
  5. 시초가 청산다음 날 09:00
P 문제

15:30에 확정되는 종가가 15:20 판단에 섞이면 백테스트가 실제로는 불가능한 수익을 보여 줍니다. 판단 시각과 종가 확정 시각이 10분 차이라 실수하기 쉬운 구조였습니다.

A 분석
  • 전체 기간 데이터를 한꺼번에 쓰는 방식은 단순하지만, 누출을 코드로 막지 못해 제외했습니다.
  • 데이터를 처음부터 시점별로 따로 저장하는 쪽이 누출 여부를 검증하기 쉬워 선택했습니다.
A 실행
  • 수집 시점 가격(결정_종가)과 확정 종가(종가)를 서로 다른 컬럼으로 저장했습니다.
  • 과거 구간은 1분봉에서 15:20 상태를 복원해 같은 형태의 패널로 만들었습니다.
  • 작업 규칙에 '관측 불가능한 가격으로 체결 가정 금지'를 명시했습니다.
R 결과 코드로 확인

연구 문서 기준으로 모든 백테스트가 15:20 시점 정보만으로 판단하고, 15:30 종가 매수와 다음 날 09:00 시초가 청산 규칙을 따릅니다.

CASE 02K-Closing Alpha개인

1틱 비용이 12bp를 넘는 종목을 순위 매기기 전에 제외해 비용에 지는 매매를 걸러냈다

P 문제

점수 상위 종목을 그대로 사면 호가 간격이 큰 저가주가 많이 들어옵니다. 1틱이 가격의 20~50bp인 종목은 세금과 슬리피지를 빼면 손실이 납니다.

A 분석
  • 상한을 6, 9, 12, 15bp와 상한 없음으로 바꿔 비교했습니다.
  • 15bp는 Sharpe가 2.88로 더 높지만 매매가 이뤄진 날이 83.3%로 12bp의 99.7%보다 적어 제외했습니다.
  • 12bp는 후보 종목 수를 7.5bp 대비 2.6배로 늘리면서 Sharpe도 높아 선택했습니다.
A 실행
  • 가격대별 호가 단위 표를 코드에 넣고 1틱 / 현재가를 계산해 12bp 초과 종목을 제외했습니다.
  • 거래세는 날짜별 세율표로, 수수료는 적용받는 증권사 우대율(왕복 약 0.73bp)로 반영했습니다.
  • 상한가 근처 종목 처리도 같은 전략 계약 안에 두었습니다.
R 결과 백테스트

5,000원 미만 종목만 사면 일평균 -12.53bp, 5,000~20,000원 구간은 +24.02bp였습니다(백테스트, 연구 문서 4절).

CASE 03K-Closing Alpha개인

겹치는 라벨을 제거한 CPCV와 교체 게이트로, 우연히 좋은 모델이 운영에 들어가는 길을 막았다

  1. 8구간 분할2구간을 시험용
  2. 앞뒤 제외시험 구간 인접 1구간
  3. 28개 분할독립 경로 7개
  4. 주간 재학습신규 모델 생성
  5. 교체 게이트순위 일치도 0.95 이상
P 문제

라벨 기간이 겹치는 데이터를 무작위로 나누면 학습과 평가가 섞입니다. 118개 전략을 비교하면 우연히 좋은 전략을 고를 위험도 있습니다.

A 분석
  • 단순 시간 분할은 평가 경로가 한 개뿐이라 한 번의 운에 좌우되어 제외했습니다.
  • 데이터를 8구간으로 나눠 2구간을 시험용으로 뽑는 조합 방식(CPCV)은 평가 경로를 여러 개 만들어 선택했습니다.
A 실행
  • CPCV(8, 2)로 28개 분할(독립 경로 7개)을 만들고, 시험 구간 앞뒤 1구간씩을 학습에서 뺐습니다.
  • 매주 재학습한 모델은 최근 20거래일 예측 순위 일치도 0.95 이상 등의 기준을 통과해야 운영 모델이 되도록 게이트를 만들었습니다.
R 결과 코드로 확인

기준 미달 모델은 운영에 올라가지 못하는 구조를 갖췄습니다. 다만 118개 중 고른 결과라 선택 편향은 남아 있고, 보정 결과는 제시하지 않았습니다.

CASE 04K-Closing Alpha개인

주문을 보내기 전에 먼저 기록하고, 응답이 불확실하면 증권사 원장으로 확인해 중복 주문을 막았다

  1. 의도 기록INTENT 디스크 저장
  2. 주문 전송SEND 기록
  3. 응답 불확실UNKNOWN 상태
  4. 원장 조회같은 주문 탐색
  5. 채택/종결ADOPT 또는 종결
P 문제

주문 응답이 타임아웃되면 접수 여부를 알 수 없습니다. 그대로 재전송하면 이중 매수가 됩니다.

A 분석
  • 재시도 횟수를 제한하는 방법은 이미 접수된 주문을 막지 못해 제외했습니다.
  • 보내기 전에 기록을 남기고, 결과가 불확실하면 증권사 원장을 조회해 맞추는 방식을 선택했습니다.
A 실행
  • 주문 의도(INTENT)와 전송(SEND)을 디스크에 먼저 쓰고 전송했습니다.
  • 응답이 불확실하면 UNKNOWN 상태로 두고, 원장에서 같은 주문을 찾으면 채택(ADOPT), 없을 때만 종결하도록 했습니다.
  • 종가는 시각, 장운영 구분코드, 현재가와 호가 조회 가격 일치의 3조건을 모두 만족할 때만 확정합니다.
R 결과 코드로 확인

상태 전이와 채택 로직, 종가 확정 조건 함수를 구현했고 단위 테스트가 있습니다. 실거래 운영 기록은 없습니다.

한계

  • 모든 수익 수치는 과거 데이터 백테스트이며, 실계좌나 모의투자의 누적 손익 기록은 없습니다. 118개 전략 중 좋은 결과를 골랐기 때문에 실제 성과는 이보다 낮을 수 있습니다.
  • 원시 데이터는 저장소에 없어 백테스트를 그대로 재현할 수 없고, 비용 모델은 제 계좌의 수수료 조건 기준입니다.
