K-Closing Alpha

장 마감 직전 정보로 종가에 사서 다음 날 시초가에 파는 퀀트

개요

15:20에 볼 수 있는 정보만으로 점수를 매겨 상위 3종목을 종가에 사고 다음 날 시초가에 파는 전략을 연구하고, 자동 실행 구조를 만들었습니다. 운영 전략의 백테스트 일평균 순수익은 +31.27bp(1bp=0.01%), 샤프지수 2.57입니다. 수익률보다 숫자가 부풀려질 곳을 먼저 막아, 미래 정보 차단·비용 반영·검증·중복 주문 방지를 프로그램 규칙으로 고정했습니다. 실거래 기록은 없고 2026.10.12부터 모의투자로 운영 경로를 리허설 중입니다.

CASE 01K-Closing Alpha개인

판단 시각과 확정 종가의 분리

  1. 15:20 수집그 시각 가격 저장
  2. 점수 산정15:20 정보만 사용
  3. 15:30 확정종가는 별도 항목
  4. 종가 매수점수 상위 3종목
  5. 시초가 청산다음 날 09:00
P 문제

15:20에 종목을 고를 때 15:30에 정해지는 종가가 섞이면 현실에서 불가능한 수익이 나옵니다. 두 시각이 10분 차이라 실수하기 쉽습니다.

  1. 설계15:20에 수집한 가격과 15:30 확정 종가를 다른 항목으로 분리 저장, 과거 데이터는 1분봉으로 15:20 당시 가격을 복원
  2. 09.14과거일을 다시 실행해도 확정 종가를 덮어쓰지 못하게 가드 추가
  3. 09.15수급 피처에 당일 미확정 값이 섞이던 룩어헤드(미래 정보 유입)를 찾아 전일 확정치로 교체, 학습과 서빙 기준 일치
A 실행
  • 작업 규칙에 '당시 알 수 없던 가격으로 체결 가정 금지'를 명시하고, 모델 번들과 실시간 대상 종목 설정이 어긋나면 실행 차단
R 결과

모든 백테스트가 15:20 정보만으로 판단하고 15:30 종가 매수·다음 날 09:00 시초가 청산을 가정합니다(연구 문서 기준). 실제로 섞여 있던 룩어헤드를 찾아 고쳤습니다.

CASE 02K-Closing Alpha개인

호가 비용 큰 종목의 사전 제외

P 문제

점수 상위에 호가 한 칸 폭이 큰 저가주가 몰립니다. 한 칸이 가격의 0.2~0.5%인 종목은 세금과 체결 가격 차이를 빼면 손실입니다.

A 분석
  • 비용 상한 6·9·15bp와 상한 없음을 비교하면 15bp의 샤프지수가 가장 높음(2.88), 운영 값은 12bp로 정했고 문서는 7.5bp 대비 후보가 2.6배로 늘어난다고 기록
  • 다만 12bp 균등 가중의 단독 행이 연구 문서에 없어, 상한 선택은 같은 조건의 비교로 확정하지 못함
A 실행
  • 가격대별 호가 단위 표로 '호가 한 칸 ÷ 현재가'를 계산해 0.12% 초과 종목은 순위 전에 제외
  • 거래세는 날짜별 세율표, 수수료는 증권사 우대율을 적용하고 상한가 근처 종목도 같은 규칙에 포함
R 결과

왕복 비용이 1칸에서 6칸으로 늘면 일평균 순수익이 +41.92bp에서 -5.88bp로 줄어, 4칸까지 이익이고 6칸에서 손실입니다. 운영 비용 상한은 12bp입니다. 백테스트

CASE 03K-Closing Alpha개인

겹침 없는 검증과 모델 교체 심사

P 문제

정답 기간이 겹치는 데이터를 무작위로 나누면 학습과 평가가 섞입니다. 118개 전략 중 우연히 좋은 것을 고를 위험도 있습니다.

  • 28개분할: 8구간 중 2구간을 시험용으로 조합
  • 7개독립 평가 경로
  • 앞뒤 1구간시험 구간 인접 구간을 학습에서 제외해 겹침 방지
  • 0.95 · 20일매주 새로 학습한 모델은 최근 20거래일 순위가 기존 모델과 0.95 이상 일치해야 운영
A 분석
  • 시간순 단순 분할은 평가 경우가 1개뿐이라 운에 좌우돼 제외, 조합 분할로 평가 경우를 늘림
R 결과

교체 심사 기준(0.95·20일)에 못 미치는 모델은 운영에 올라가지 못합니다.

CASE 04K-Closing Alpha개인

주문 전 기록으로 중복 주문 차단

  1. 의도 기록주문 내용을 디스크에 저장
  2. 주문 전송전송 사실 기록
  3. 응답 불확실미확인 상태로 표시
  4. 체결 내역 조회같은 주문 탐색
  5. 인정/종결있으면 인정
P 문제

주문 후 증권사 응답이 오지 않으면 주문이 접수됐는지 알 수 없습니다. 다시 보내면 같은 종목을 두 번 사게 됩니다.

  1. 09.21하루 두 번 도는 진입 단계에서 두 번째 실행이 줄어든 현금으로 다시 사이징해, 체결된 주문을 더 작은 주문으로 덮어씀(예: 301주→50주). 당일 진입 기록이 있으면 건너뛰도록 수정
  2. 10.12임대 서버(VPS)의 주문 경로를 모의투자로 전환해 리허설 시작. 모의 장중 조회가 1.3~4.6초 걸려 5초 제한에 가깝고, 취소된 주문 행이 기존 주문 후보로 오인될 수 있어 보정
  3. 10.15전일 미확인 주문의 이월 복구와 운영자 수동 해소 경로 추가
  4. 11.07실거래 주문 한도를 환경변수로 명시하지 않으면 실거래 연결을 거부
A 실행
  • 주문 의도와 전송 사실을 먼저 기록하고, 응답이 불확실하면 체결 내역에 같은 주문이 있을 때만 인정, 종가 확정은 시각·장 운영 상태·가격 일치 3조건으로 판단
R 결과

주문 상태 변화, 기존 주문 인정, 종가 확정 판단을 구현해 단위 테스트를 작성했고, 모의투자 리허설에서 나온 결함을 위 이력대로 고쳤습니다. 운영 기록

한계

  • 수익 수치는 모두 백테스트이고, 실계좌·모의투자 손익 기록은 없음(모의투자는 운영 경로 리허설 단계)
  • 118개 중 고른 결과라 실제 성과는 더 낮을 수 있고 선택 편향 보정 결과는 제시하지 않음. 대표 수치(+31.27bp)는 운영 전략 기준이고, 연구 문서의 +34.58bp는 12bp 상한에 역틱 가중을 더한 연구용 변형이라 운영 경로에는 해당 가중이 없음
  • 연구 문서 안에 불일치가 있음: 2틱 조건의 두 표가 +34.58bp와 +32.36bp를 모두 샤프 2.73으로 적고, 비용 상한 비교의 조건이 섞여 있음. 룩어헤드 수정 전후의 수치 차이는 기록이 없음
  • 연구 문서가 저장소 밖에 있고 원본 데이터가 없어 재검증과 재현이 어렵고, 비용은 내 계좌 수수료 기준
