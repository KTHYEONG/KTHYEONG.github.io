장 마감 직전 정보로 종가에 사서 다음 날 시초가에 파는 퀀트

개요

동작 흐름

사례

주문 응답이 불확실하면, 다시 보내기 전에 먼저 확인

보내기 전에 기록 → 증권사 주문 목록과 대조

문제

주문 뒤 응답이 불확실하면 접수 여부를 알 수 없고, 그대로 다시 보내면 두 번 살 수 있습니다.

판단

재시도 횟수를 줄여도 이미 접수된 주문은 막지 못합니다. 보내기 전에 기록하고, 확인을 먼저 합니다.

결과

접수된 주문은 그대로 인정하고, 불확실한 상태에서는 확인 없이 다시 보내지 않습니다.

가상·모의 매매를 돌리며 찾은 실패를 수정

조회 1회 실패로 모의 매수 0건 → 마감 전까지 재시도 운영 기록
겪은 문제와 위험고친 방법
주문 가능 금액 조회가 한 번 실패해, 마감까지 7분 넘게 남았는데 그날 매수 0건읽기 조회는 마감 전까지 반복해서 재시도. 끝내 알 수 없으면 사지 않고 알림
체결 확인을 당일 한 번만 해서, 실패하면 산 종목이 다음 날 매도와 알림에서 빠질 수 있었음다음 실행에서 확인 못 한 주문부터 확정하고, 남으면 계속 알림
가상 매매가 하루 두 번 실행되어 앞선 기록을 덮어씀 (301주 → 50주)당일 기록이 있으면 두 번째 실행은 건너뜀

호가 한 칸이 큰 종목은 순위를 매기기 전에 제외

왕복 비용 1칸 → 6칸: +41.92 → -5.88bp 백테스트

전략의 수익은 거래 비용 가정에 크게 좌우됩니다. 그래서 호가 한 칸이 가격의 0.12%(12bp)를 넘는 종목은 후보에서 뺍니다.

결론호가 한 칸이 12bp 이하인 종목만 후보로 사용

상한을 7.5bp에서 12bp로 넓히자 후보가 2.6배로 늘고, 순위 모델의 선택 폭이 커져 샤프지수가 0.84 높아졌습니다.

AI 도구가 반복해 넣은 '기본 꺼짐' 스위치를 규칙과 테스트로 차단

플래그 7개 삭제, 새 스위치는 등록 필수 운영 기록
항목이전이후
새 기능 배포꺼진 채 배포되어 서버에서 다시 켜야 적용켜진 채 배포하고, 문제가 있으면 되돌려 재배포
서버 설정 유실서버 환경을 다시 만들며 설정이 빠져, 수집 작업이 조용히 꺼짐항상 켜 두던 스위치 7개와 꺼짐 분기를 삭제
새 스위치AI 도구가 같은 패턴을 반복해 추가등록부에 없으면 정책 테스트 실패
