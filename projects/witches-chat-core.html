Witches-Chat-Core

근거 조항과 함께 답하는 온프레미스 규정 RAG 챗봇

개요

경북대 학사 규정은 한글(HWP)·워드(DOCX)·PDF로 흩어져 있고, 클라우드 AI에는 규정과 개인정보를 보내기 어렵습니다. 학교 안에서 규정을 검색해 근거와 함께 답하는 챗봇을 팀으로 만들었고, 저는 앞단인 규정 문서를 Markdown으로 바꾸고 조·항 구조를 표시하는 일을 맡았습니다.

CASE 01Witches-Chat-Core팀

HWP·DOCX·PDF를 Markdown 하나로 통일

  1. 규정 원본HWP·DOCX·PDF
  2. 형식별 변환형식마다 변환기
  3. 구조 표시조·항·호 기호
  4. 잡음 정리깨진 문자 제거·표 분리
  5. 쪼개기 전달구간 정보 포함
P 문제

규정이 세 가지 파일 형식으로 섞여 있고, 조·항·호 계층이 의미를 정합니다. 형식별로 다루면 문서 쪼개기와 검색도 형식마다 따로 만들어야 합니다.

A 분석
  • 형식별 문서 쪼개기: 팀원이 형식마다 따로 처리해야 해 제외
  • Markdown: 문서 쪼개기의 표준 입력, 제목·목록·표 표현 가능
  • 팀원 모두 같은 입력 형식 사용 가능
A 실행
  • 형식별 변환기를 두되 결과 구조는 동일하게
  • 초기에는 HWP를 DOCX로 수동 변환
  • 이후 HWP 직접 변환 추가
R 결과

원본 HWP 20·DOCX 5·PDF 4개를 Markdown 28개로 정리해 문서 쪼개기 단계에 전달.

CASE 02Witches-Chat-Core팀

원문은 두고 조·항·호 계층 표시만 추가

P 문제

조·항·호·목이 구분 없는 줄글이면 문서를 쪼갤 때 조항 중간이 잘려 의미가 끊길 수 있습니다.

A 분석
  • 문장 다듬기·요약: 조항 의미가 달라질 수 있어 제외
  • 원문 유지, 표시만 추가
A 실행
  • 줄 앞머리(제1장, 제1조, ①, 1., 가. 등) 인식
  • 제목·굵은 소제목·목록으로 표시
  • 학칙 변환 결과에서 장·절 제목, 조 소제목, 항·호 목록 확인
R 결과

계층이 Markdown 기호로 남아 문서 쪼개기 단계가 구조를 읽을 수 있음. 단서 문장 등 예외 조항은 원문 순서 유지.

CASE 03Witches-Chat-Core팀

표와 신청서 양식을 구분해 본문에서 분리

P 문제

신청서 서식과 빈 칸 많은 표가 본문에 섞이면 검색 결과에 불필요한 내용이 끼고 문서 쪼개기도 어렵습니다.

A 분석
  • 표 일괄 처리: 내용 표와 양식 구분 불가, 제외
  • 빈 칸 비율 등 표 모양과 양식 표현으로 판별
A 실행
  • 빈 칸 많은 여러 열 표, 양식 표현(예/아니오), 정해 둔 글자 패턴이면 양식으로 판별
  • 양식은 본문과 따로 변환
  • 표를 따로 벡터로 변환해 저장 가능
R 결과

양식 표가 본문과 분리되어 문서 쪼개기 단계로 전달. 판별 정확도는 미측정.

CASE 04Witches-Chat-Core팀

DOCX·PDF 변환, 범용 도구 대신 직접 읽기

P 문제

큰 규정집은 DOCX·PDF 변환이 오래 걸려, 규정을 고칠 때마다 다시 변환하기 부담스러웠습니다.

A 분석
  • 병목: 워드 변환 도구가 문서를 통째로 객체화하는 과정, PDF 변환 도구의 글꼴·정렬·표 처리
  • 설정 조정보다 필요한 부분만 직접 읽는 방식 선택
A 실행
  • DOCX: 파일 내부 XML에서 본문·표·텍스트 상자를 직접 읽기
  • 깨진 제어 문자를 한 번에 제거
  • PDF: 표 영역과 본문 덩어리를 나눠 읽기
R 결과

커밋 메시지 기준 PDF 변환 약 70초에서 15초. 측정 파일·환경 기록 없는 참고 수치. 운영 기록

한계

  • 전처리 구간 자동 테스트 없음, 변환 전후 글자 수 비교 로그(85% 미만이면 경고)와 눈으로 확인
  • 팀 악성 질문 차단 결과는 직접 만든 입력 210개 기준, 실제 질의 평가 아님
  • 이미지 변환은 글자 인식(OCR) 도구 설치 후 검증 필요
