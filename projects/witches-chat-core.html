근거 조항과 함께 답하는 온프레미스 규정 RAG 챗봇

개요

대학 규정을 질문하면 근거 문서를 찾아 답하는 온프레미스 RAG 챗봇 산학협력 프로젝트(협력기관 (주)위치스)입니다. 저는 한글(HWP)·워드(DOCX)·PDF 규정을 챗봇이 읽을 수 있는 Markdown으로 바꾸는 전처리를 맡았습니다. 팀의 보안 가드레일 연구는 학술대회 논문으로도 이어졌습니다.

사례

AI 이해와 청킹을 고려해 문서를 Markdown 하나로 통일

원본 29개 파일 → Markdown 28개 (규정 24종)

HWP·DOCX·PDF로 흩어진 규정을 어떤 형식으로 모을지가 이후 단계의 품질과 작업량을 좌우합니다. 두 가지를 보고 Markdown을 선택했습니다.

AI가 이해하기 좋은 형식

  • 제목·목록·표 구조를 간단한 기호로 남길 수 있어, AI가 문맥을 파악하는 데 가장 효과적이라고 판단

청킹이 쉬워지는 단일 입력

  • 원본 형식이 달라도 하나의 방식으로 나눌 수 있어, 이후 청킹 작업이 단순해짐
원본 형식파일 수변환 방법
HWP20개처음에는 파일을 DOCX로 수동 변환해 처리했고, 이후 HWP를 바로 읽는 변환을 추가
DOCX5개문서 내부의 XML을 직접 읽어 본문·표·글상자를 순서대로 변환
PDF4개표 영역과 본문 글을 나눠 읽어 변환
속도 개선
큰 규정집은 기존 라이브러리 처리가 느려 문서 내용을 직접 읽도록 변경. PDF는 약 70초 → 15초
형식 확장
채팅 화면에서 올리는 텍스트·엑셀·PPT·음성 파일 등으로 변환 범위를 넓힘

결론AI가 읽기 좋고 청킹하기 편한 하나의 형식으로 정리

PDF는 속도를 위해 원문 글과 표를 읽는 방식으로 바꿔, 조항 계층 표시는 붙이지 않습니다.

DOCX 규정: 문장은 그대로 두고 계층 표시만 추가

조는 제목, 항·호·목은 들여쓴 목록

조·항·호가 같은 줄글이 되면 검색 단위로 나눌 때 조항 중간이 잘릴 수 있습니다. 문장을 다듬으면 뜻이 달라질 수 있어, 줄 앞에 표시만 붙였습니다.

##### 제12조(공적결석자 등에 대한 출석인정) ① … 다음 각 호의 어느 하나에 해당하여 … - 7 의사 진단에 따라 격리가 필요한 법정전염병 감염자: 해당기간 - 8 경조사 등에 의한 사유로서 아래 기준에 해당한 때

제목
편·장·절·관은 # 1~4개, 조·부칙·별표는 # 5개
목록
항(①) → 호(1.) → 목(가.) 순서로 한 단계씩 들여쓰기

결론원문 문장을 고치지 않고 조항의 계층을 남김

조 제목과 ①이 한 줄이면 줄 전체가 제목이 되고, 호 번호의 마침표가 빠지는 한계가 있습니다.

DOCX 변환에서 내용이 빠지는지 글자 수로 점검

원본의 85%보다 적으면 경고

규정 일부가 빠져도 겉으로는 알기 어렵고, 빠진 채 검색에 쓰이면 답변의 근거가 사라집니다. 긴 규정을 눈으로 대조하기는 어렵습니다.

결론변환할 때마다 큰 누락을 자동으로 확인

빠진 양만 알 수 있고 위치는 모르며, 85% 기준은 따로 검증한 값이 아닙니다.

청킹 담당과 넘겨줄 형식을 맞추고 구현

본문 앞에 블록 정보를 붙여 전달

청킹 단계는 각 조각이 문단인지 목록인지 표인지 알아야 하는데, 본문만으로는 구분하기 어렵습니다. 담당 팀원과 주고받을 정보를 먼저 정한 뒤 구현했습니다.
