개요

가격·수급·재무 지표 52개로 LightGBM이 종목 순위를 매기고, 지수선물 포지션으로 시장 노출을 조절하는 전략입니다. 백테스트가 미래 정보와 반복 조정으로 부풀려지지 않도록 검사와 판정 규칙을 코드에 두었고, 서버는 장 시작 전에 확정한 목표를 가상 장부에만 기록합니다.

동작 흐름

사례

미래 데이터를 바꿔도 과거의 결정이 그대로인지 검사

결과가 달라지면, 코드가 미래 값을 미리 쓴 것

백테스트에서 코드 실수로 그날 알 수 없던 값을 쓰면 수익률이 실제보다 높아집니다. 그래서 과거의 하루를 검사일로 정하고, 그다음 날부터의 데이터를 엉터리 값으로 바꿔 다시 계산합니다.

적용
전략을 평가할 때마다 검사일 3개를 뽑아 검사하고, 하나라도 다르면 불합격

결론저장된 평가 29건 모두 불일치 0건

일부러 미래 값을 쓰게 만든 코드는 테스트에서 불합격해, 검사가 실제로 잡아내는 것도 확인했습니다.

재무 실적은 공시된 뒤부터 사용

결산일이 아니라 실제 공시 접수일 기준

연간 실적은 12월 31일 기준의 값이지만 공시는 다음 해에 나옵니다. 결산일부터 쓰면 아무도 모르던 실적을 미리 아는 셈입니다.

정정 공시
나중에 정정된 값이 처음 공시일의 값처럼 기록되던 문제를 찾아, 정정이 접수된 뒤부터 쓰도록 수정

전략 변경은 현재 전략과 비교해 판정하고 기록

변경안 6건: 통과 3 · 기각 2 · 예외 채택 1 백테스트

전략을 계속 바꿔 보면 과거에만 맞는 결과를 고르게 됩니다. 그래서 변경안은 성장률이 확실히 높거나, 성장 손실이 연 3%p 이내이면서 큰 손실 위험이 확실히 줄 때만 통과합니다.

통과 3건

  • KOSPI 200 추세 오버레이 도입
  • 두 번째 지수 헷지 추가
  • 지표·보유 구성 변경

기각 2건

  • 나아졌다고 보기 어려운 변경안

예외 채택 1건

  • 변동성이 커지면 선물 포지션 축소
예외 이유
성장 손실이 허용 범위인지는 입증하지 못했지만, 큰 손실 위험이 주는 것은 확인돼 위험 제한 규칙으로 채택
예외 조건
성장률 검정만 면제할 수 있고, 사유를 남기지 않으면 코드가 거부

서버를 돌리며 찾은 실패를 수정

백업 누락으로 결정 입력 유실 → 백업 대상과 삭제 순서 수정 운영 기록
겪은 문제고친 방법
백업 목록에서 일부 데이터가 빠진 채 정리 작업이 이전 데이터를 삭제해, 과거 결정의 입력이 영구 유실백업 대상을 설정 파일 하나로 관리해 누락을 차단
정리 작업이 백업보다 먼저 실행돼, 아침 결정에 쓴 데이터가 백업 전에 삭제백업이 성공한 뒤에만 정리하도록 순서를 변경
장전 확정이 이틀 연속 실패. 원인은 몇 시간 전부터 있었지만 확정 시각에야 드러남확정과 같은 검사를 07:30에 먼저 실행

주의 사항
같은 기간에서 전략을 고른 결과모든 비교를 2018~2026.10 한 구간에서 했고, 따로 남겨 둔 검증 구간은 없습니다.
판정 규칙도 연구 중에 보강손실 위험 감소를 인정하는 기준은 연구 중에 추가했습니다.
초기 운영 기록 일부 유실운영 초기의 일부 결정은 입력이 남지 않아 다시 계산할 수 없습니다.
실제 체결슬리피지·시장 충격 가정과 실제 체결의 차이는 확인하지 못했습니다.
저장소만으로 재검증 불가전략 설정과 결과 파일은 비공개이고 원본 데이터는 공개하지 않았습니다.
