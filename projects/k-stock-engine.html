K-Stock Engine

국내주식 다중 팩터 전략 연구와 장전 목표 가상 기록

개요

백테스트가 미래 정보와 반복 조정으로 부풀려지지 않도록, 공시 시각 기준 데이터와 사전에 선언한 평가 규칙으로 전략을 검증합니다. 2026-10-11부터 서버에서 매일 장전에 목표 포트폴리오를 확정해 가상 장부에만 기록하고, 실주문은 코드에서 막혀 있습니다.

CASE 01K-Stock Engine개인

공시된 시각부터 데이터를 쓴다

모든 데이터에 사용 가능 시각이 붙고, 이 규칙은 단위 테스트로 검증합니다.
P 문제

분기 재무제표는 분기말 값이지만 실제 공시는 최대 45일 뒤입니다. 분기말 날짜로 합치면 백테스트가 그 시점에는 몰랐던 정보를 씁니다.

재무 데이터를 합치는 기준
분기말 날짜 기준접수 시각 기준(현재) 선택
사용 가능 시점분기말 직후접수 다음 거래일 장 시작
종목별 공시 시점 차이지연 일수를 일률로 가정실제 접수 시각 사용, 가정 불필요
미래 정보 혼입가능연구·평가가 공개 시각 이전 데이터만 조회
A 분석
  • 분기말에 며칠 지연을 두는 방식은 간단하지만 종목마다 공시 시점이 달라 일률 값을 정할 수 없어 제외
A 실행
  • 수집물마다 받은 시각을 영수증으로 남기고, 정규화 단계에서 접수 시각 다음 거래일 장 시작을 사용 가능 시각으로 계산
  • 모든 데이터가 '언제부터 알 수 있었는지'를 갖는 데이터 계약을 코어 계층에 두고 연구·평가가 이를 따르게 함
R 결과

모든 데이터에 사용 가능 시각이 붙고, 이 규칙은 단위 테스트로 검증합니다.

CASE 02K-Stock Engine개인

한 증권사 계정을 서버 전체가 나눠 쓴다

한도와 토큰 처리 규칙을 테스트로 검증합니다.
P 문제

한 서버의 여러 프로젝트가 같은 증권사 계정을 씁니다. 프로세스 안에서만 속도를 제한하면 서로의 호출량을 몰라 한도를 넘고, 토큰 발급도 동시에 겹칩니다.

  • 초당 18건서버 전체 호출 상한, 공유 디렉터리의 파일 락에 다음 호출 가능 시각을 기록
  • 3단계중요도별 대기 허용: 긴급은 즉시, 일반은 최대 1.0초, 대량 수집은 최대 0.25초까지만 앞당겨 예약
  • 1회 발급토큰은 키 해시별 락으로 한 번만 발급, 기다리는 프로세스는 받은 토큰 재사용
A 분석
  • 프로세스 안 제한기는 구현이 쉽지만 다른 프로세스를 보지 못해 제외, 별도 중앙 서버는 운영 부담이 커 제외
A 실행
  • 파일 락 기반 제한기를 만들어 호출 슬롯을 예약하고 우선순위로 중요한 호출을 보호
  • 공유 디렉터리 표식이 없으면 실행을 거부해 제한이 공유되지 않은 채 도는 상황을 차단
R 결과

한도와 토큰 처리 규칙을 테스트로 검증합니다. 같은 서버에서 도는 다른 수집 프로젝트와 계정을 공유하는 문제가 이 제한기의 출발점입니다.

구현 코드admission.py

CASE 03K-Stock Engine개인

전략은 사전에 정한 통계 기준으로만 승격

전략 변경이 '더 좋아 보인다'가 아니라 설정 파일에 선언된 기준으로 승격됩니다.
P 문제

전략을 계속 바꿔 보면 과거 데이터에만 맞는 결과를 고르게 됩니다. 점수 하나로는 과적합과 우연을 구분하기 어렵고, 기준을 결과를 보고 고치면 의미가 사라집니다.

A 분석
  • 단일 샤프지수는 시험 횟수를 반영하지 못해 제외, 매매 요일에 따라 성과가 달라지는 주 1회 리밸런싱은 자금을 5개 슬리브로 나눠 매매일 분산
A 실행
  • 같은 구간의 짝지은 부트스트랩 비교와 다중 검정 보정(본페로니)을 통과해야 새 전략이 기준 전략을 대체
  • 슬리피지 비용 격자(0~1.5틱), 파산 확률 가드, 지연·플라시보 시나리오를 함께 보고
R 결과

전략 변경이 '더 좋아 보인다'가 아니라 설정 파일에 선언된 기준으로 승격됩니다. 선언 날짜와 근거는 설정 파일 주석에 남깁니다.

  • 63일 × 4,000회63거래일 블록 부트스트랩으로 5년 경로를 4,000개 만들어 평가
  • 하위 10%평균이 아니라 나쁜 경우(하위 10%)의 성장률을 목적 값으로 사용
  • 연 3%p사전 선언한 허용 한계: 통계적으로 꼬리 위험 감소를 보인 대신 감수할 최대 성장 손실, 결과를 본 뒤 조정하지 않음
  • 시드 3개점수 모델은 시드 11·12·13 평균과 비교해 시드 운을 제거

구현 코드protocol.tomlchampion.py

CASE 04K-Stock Engine개인

성공 기록도 믿지 않는 무인 운영

서버는 2026-10-11부터 장전 목표 확정과 가상 장부 기록을 반복하고, 점검표는 2026-11-02 실제 서버에서 검증했습니다.
P 문제

자동 작업이 성공이라고 기록해도 데이터가 비었거나 일부만 쓰인 경우가 있습니다. 예외가 없으면 성공으로 보는 방식은 부분 실패를 놓칩니다.

  • 4상태모든 작업이 OK · DEGRADED · NO_DECISION · SKIPPED 중 하나로 기록, SKIPPED는 사유 필수
  • 09:00 전장전 목표 봉인 기한: 늦게 확정하면 OK가 아니라 DEGRADED로 기록
  • 4가지 사건만장전 결정 미봉인, 기록 판독 불가, 백업 2일 이상 중단, 같은 작업 3거래일 연속 실패만 메일 발송
A 실행
  • 일일 감사가 작업 기록과 실제 산출물(봉인 체인, 장부 상태)을 대조하고, 서버 점검표(or-vps 런북)가 같은 서버의 다른 프로젝트와 한 체계로 매일 판정
  • 아침 봉인이 실패하면 늦은 봉인을 자동 실행, 같은 사건은 하루 한 번만 알리고 해결되면 한 줄로 알림
R 결과

서버는 2026-10-11부터 장전 목표 확정과 가상 장부 기록을 반복하고, 점검표는 2026-11-02 실제 서버에서 검증했습니다. 실주문 경로는 증거 4가지가 없으면 예외로 막힙니다. 운영 기록
