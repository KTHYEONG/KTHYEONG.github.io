K-Stock Engine

국내주식 팩터 전략의 연구·검증과 장전 목표 가상 기록

개요

가격·수급·재무 지표 52개로 LightGBM이 종목 순위를 매기고, 지수선물 포지션으로 시장 노출을 조절하는 전략입니다. 백테스트가 미래 정보와 반복 조정으로 부풀려지지 않도록 검사와 판정 규칙을 코드에 두었고, 서버는 장 시작 전에 확정한 목표를 가상 장부에만 기록합니다.

사례

미래 데이터를 바꿔도 과거의 결정이 그대로인지 검사

결과가 달라지면, 코드가 미래 값을 미리 쓴 것

백테스트는 과거 데이터를 한꺼번에 놓고 계산하므로, 코드 실수로 그날에는 알 수 없던 값을 쓸 수 있고 수익률이 실제보다 높아집니다. 이를 찾으려고 과거의 하루를 검사일로 골라, 그다음 날부터의 데이터를 엉터리 값으로 바꾸고 다시 계산합니다. 아래는 검사일이 2022.06.15인 경우의 예입니다.

검사 방법과 결과

검사일
평가할 때마다 평가 기간에서 3일을 뽑아 각각 검사
바꾸는 값
시세, 지표 원본, 지수, 배당, 현금 수익률
비교 대상
주식 목표 비중, 선물 결정, 계좌 평가액 (점수 모델도 다시 학습해 계산)
다르면
평가 불합격이 되어 전략에 반영할 수 없음
결과
저장된 평가 리포트 29개 모두 불일치 0건. 일부러 미래 값을 쓰게 만든 코드는 테스트에서 불합격

3일만 확인하는 표본 검사이며, 청산 정보 일부는 바꾸지 않습니다. 또 데이터를 알게 된 날짜가 처음부터 잘못 적혀 있으면 잡지 못해, 다음 사례의 규칙으로 따로 막습니다.

재무 실적은 공시된 뒤부터 사용

결산일이 아니라 실제 공시 접수일 기준

실적의 기준일(결산일)과 실적이 공개되는 날은 다릅니다. 연간 실적은 12월 31일 기준이지만, 회사는 다음 해 3월 말(결산 후 90일)까지 공시하면 됩니다. 그 전에는 투자자가 알 수 없으므로, 실제 접수일을 확인해 사용 시점을 정합니다.

추가로 고친 문제적용한 규칙
09.24 나중에 정정된 실적이, 처음 공시한 날에 이미 알던 값처럼 기록됨 (공시 조회 API인 OpenDART가 최신 값을 돌려줌)처음 공시일과 정정 접수일 중 늦은 날을 기준으로 사용

전략 변경은 현재 전략과 비교해 판정하고 기록

변경안 6건: 통과 3 · 기각 2 · 예외 채택 1 백테스트

전략을 계속 바꿔 보면 과거에만 맞는 결과를 고르게 됩니다. 변경안은 현재 전략과 같은 날짜들을 짝지어 다시 뽑아 비교합니다(63거래일 블록, 4,000회). 성장률이 통계적으로 높거나, 성장 손실이 연 3%p를 넘지 않으면서 큰 손실 위험이 줄었다고 확인될 때 통과합니다.

10.08지표·보유 구성 변경통과: 성장률 개선

채택 이유
큰 손실 구간의 개선(+3.0%p)은 신뢰 하한까지 확인돼, 위험을 제한하는 규칙으로 판단

여러 프로젝트가 증권사 호출 한도를 함께 지키는 제한기

계정 하나의 호출 순서를 파일 잠금으로 공유

한 서버의 여러 프로젝트가 같은 증권사 계정을 씁니다. 프로세스 안에서만 속도를 제한하면 서로의 호출량을 몰라 한도를 넘습니다. 별도 중앙 서버는 운영 부담이 커서, 공유 파일에 다음 호출 시각을 예약하게 했습니다.
