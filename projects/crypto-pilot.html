Crypto Pilot

바이낸스 선물 전략 검증부터 모의 자동 집행까지

개요

바이낸스 무기한 선물 시장을 대상으로 백테스트에서 24시간 자동 집행까지 한 저장소에서 다루는 코인 자동 투자 프로젝트입니다. 과거 데이터로 만든 전략이 실제로 돌리면 달라지는 원인(미래 정보 사용, 체결 비용, 강제청산, 여러 번 시도한 편향)을 코드 단계에서 줄이는 데 집중했습니다. 집행 데몬은 현재 주문을 내지 않고 체결만 가정하는 모의(paper) 모드로 운영하며, 모든 수익률은 과거 데이터를 다시 돌린 재현 시뮬레이션입니다.

CASE 01Crypto Pilot개인

수익 극대화 대신 강제청산 규칙을 넣은 계좌 시뮬레이션으로 레버리지 정하기

  1. 수익 분포시점별 갱신
  2. 배율 선택기대 성장 최대
  3. 상한 적용10배·증거금 90%
  4. 계좌 시뮬유지증거금·펀딩비
  5. 청산 확인강제청산 여부
P 문제

같은 신호도 레버리지를 높이면 수익이 커 보이지만, 급락 때 유지증거금(포지션 유지에 필요한 최소 증거금)이 모자라면 강제청산됩니다. 비중만 계산하는 백테스트는 이 위험과 최소 주문 수량 때문에 거절되는 주문을 반영하지 못합니다.

A 분석
  • 전체 기간 수익률을 보고 고정 배율을 고르면 미래 정보를 쓴 셈이라 제외했습니다.
  • 과거 수익만으로 매일 배율을 다시 정하는 방식은 그 시점에 알 수 있는 정보만 쓰므로 선택했습니다.
  • 배율을 정하는 것과 별개로, 증거금 규칙을 넣은 계좌 시뮬레이터가 있어야 청산 여부를 확인할 수 있다고 판단했습니다.
A 실행
  • 신호 수익률 분포를 시점마다 갱신해 기대 로그 성장이 가장 큰 배율을 고르고, 상한 10배와 증거금 한도(초기 증거금의 90%)를 두었습니다.
  • 심볼별 유지증거금 구간, 펀딩비, 수수료, 최소 주문 단위를 반영하는 계좌 시뮬레이터를 구현했습니다.
R 결과 재현 시뮬레이션

재현 시뮬레이션($1,000, 2021-04 ~ 2026-10)에서 강제청산 0회, MDD -51.2%였습니다. 평균 배율이 약 3.8배라 낙폭이 커서 실제 운용에서 버티기 어려운 수준이라는 점도 한계로 적어 두었습니다.

CASE 02Crypto Pilot개인

종가 체결 가정 대신 3분봉으로 지정가 체결을 재현하기

  1. 주문 발생지정가 주문
  2. 3분봉 순회30분 구간
  3. 체결 판정지나간 만큼만
  4. 월 단위 이월보유·대기 주문
  5. 동치 검증전체 처리와 비교
P 문제

1시간봉 종가에 바로 체결된다고 가정하면 수수료, 호가 차이, 지정가 미체결이 모두 빠져 실제와 결과가 달라집니다.

A 분석
  • 시장가(테이커)는 체결이 확실하지만 수수료가 높아(이 프로젝트 설정 6bp, 1bp=0.01%) 제외했습니다.
  • 지정가(메이커)는 수수료가 낮지만(2bp) 체결이 안 될 수 있어, 체결 여부를 가격 경로로 판정해야 했습니다.
  • 5.25년치 3분봉을 한 번에 올리면 메모리가 부족해, 월 단위로 나눠 처리하되 결과는 한 번에 처리한 것과 같아야 한다고 정했습니다.
A 실행
  • 주문 시점 이후 3분봉 10개 구간(30분) 동안 가격이 지정가를 지나간 만큼만 체결로 인정하는 집행 시뮬레이터를 구현했습니다.
  • 월 단위로 읽으며 보유 수량과 대기 주문을 다음 구간으로 넘기도록 했습니다.
  • 월 단위 처리 결과와 전체 한 번에 처리한 결과가 같은지 동치 테스트로 확인합니다.
R 결과 코드로 확인

지정가 중심 집행으로 정하고 이를 계좌 시뮬레이션의 기본 집행 방식으로 썼습니다. 월 단위 처리가 전체 처리와 같은 결과를 내는지는 테스트로 검증합니다.

CASE 03Crypto Pilot개인

전략 후보를 여러 번 시험한 편향을 시험 횟수 기록과 DSR로 보정하기

  1. 후보 시험매번 기록 남김
  2. 횟수 반영52줄 기록
  3. DSR 판정0.95 이상만
  4. 매니페스트accept 기록
  5. 홀드아웃07-01 이후 분리
P 문제

전략 후보를 계속 바꿔 시험하면 우연히 좋은 결과가 나온 후보를 고르게 됩니다.

A 분석
  • 최종 결과 하나만 보고 판단하면 시도 횟수가 숨겨져 과대평가되므로 제외했습니다.
  • 시험 횟수를 기록하고, 그 횟수만큼 샤프지수를 깎아 보는 DSR(Deflated Sharpe Ratio)을 승격 기준으로 쓰기로 했습니다.
  • 설계에 쓴 데이터와 이후 구간(홀드아웃)을 나눠 두어야 사후 확인이 가능하다고 판단했습니다.
A 실행
  • 시험할 때마다 기록을 남겨(52줄) DSR 계산에 시도 횟수로 반영했습니다.
  • DSR 0.95 이상일 때만 승격 매니페스트에 올리고, 기준값과 판정(accept)을 함께 기록합니다.
  • 설계 데이터는 2026-07-01까지로 고정하고 그 이후는 홀드아웃으로 남겼습니다.
R 결과 백테스트

승격 매니페스트에 dsr_min 0.95와 accept 판정이 기록되어 있습니다. 홀드아웃(2026-07 ~ 10)을 포함한 시뮬레이션은 CAGR +212.7%로 설계 구간(+220.4%)과 비슷했지만, 홀드아웃이 3개월로 짧다는 한계가 있습니다.

CASE 04Crypto Pilot개인

주문 시각과 겹치지 않는 무중단 배포 만들기

  1. 코드 변경수집 코드 수정
  2. 지문 비교AST 해시
  3. 대기 확인결정 시각·락
  4. 슬롯 교대Blue/Green
P 문제

매일 정해진 시각의 주문 직전·직후에 배포하면 주문이 지연되거나 시세 수집이 끊길 수 있습니다.

A 분석
  • 컨테이너를 매번 재시작하는 방식은 웹소켓이 끊겨 데이터가 비므로 제외했습니다.
  • 배포 시각을 사람이 매번 피하는 방식도 실수하기 쉬워 제외했습니다.
  • 수집 코드가 실제로 바뀐 경우에만 교대하고, 결정 시각 전후에는 기다리게 하는 자동 규칙을 선택했습니다.
A 실행
  • 수집 데몬을 Blue/Green 두 슬롯으로 두고 교대하도록 했습니다.
  • 수집 코드를 AST(문법 트리)로 정규화해 해시한 값으로 코드 변경 여부를 판단합니다.
  • 결정 시각 전후와 라이브 락이 잡혀 있을 때는 배포를 대기시킵니다.
R 결과 코드로 확인

지문 계산과 대기 조건을 단위 테스트로 검증합니다. 수치로 측정한 배포 중단 시간은 없습니다.

한계

  • 모든 수익률은 재현 시뮬레이션이며 실제 돈으로 운용한 결과가 아닙니다. 집행 데몬은 아직 모의(paper) 모드입니다.
  • 평균 배율 약 3.8배, MDD -51%로 실제 운용에서 버티기 어렵고, 펀딩 손익의 약 91%가 상위 5개 종목에 몰려 있으며, 홀드아웃은 3개월로 짧습니다.
