Crypto Pilot

바이낸스 선물 전략 검증과 모의 자동 매매

개요

바이낸스 무기한 선물의 백테스트부터 24시간 자동 매매까지 한 저장소에서 다룹니다. 미래 정보 사용, 체결 비용, 강제청산, 반복 시험으로 생기는 착시를 줄였습니다. 자동 매매는 모의 모드이며 모든 수익률은 과거 데이터 재현 시뮬레이션입니다.

CASE 01Crypto Pilot개인

강제청산 규칙을 넣은 계좌 시뮬레이션으로 레버리지 배율 결정

  1. 수익 분포시점별 갱신
  2. 배율 선택복리 성장 최대
  3. 상한 적용10배·담보금 90%
  4. 계좌 시뮬담보금 규칙·펀딩비
  5. 청산 확인강제청산 여부
P 문제

빌린 돈으로 배율을 높이면 수익은 커 보여도, 급락해 담보금이 모자라면 포지션이 강제로 정리됩니다. 비중만 계산하는 백테스트는 이를 알 수 없습니다.

A 분석
  • 전체 기간 수익을 보고 배율 하나로 고정: 미래 정보를 쓴 셈이라 제외
  • 그날까지의 수익만으로 매일 배율 재계산: 당시 정보만 사용, 선택
  • 강제청산 여부 확인에는 담보금 규칙을 넣은 계좌 시뮬레이터 필요
A 실행
  • 그 시점까지의 수익 분포로 장기 복리 성장이 가장 큰 배율 선택
  • 배율 상한 10배, 담보금 사용 한도는 초기 담보금의 90%
  • 강제청산 기준 담보금 구간, 펀딩비, 수수료, 최소 주문 단위 반영
R 결과

재현 시뮬레이션($1,000, 2021-04 ~ 2026-10)에서 강제청산 0회, 최대 낙폭 -51.2%. 평균 배율 약 3.8배라 낙폭이 큰 점은 한계로 기록. 재현 시뮬레이션

CASE 02Crypto Pilot개인

종가에 체결됐다는 가정 대신 3분 단위로 지정가 체결 재현

  1. 주문 발생지정가 주문
  2. 3분 단위 추적30분 구간
  3. 체결 판정지나간 만큼만
  4. 월 단위 이어가기보유·대기 주문
  5. 결과 비교전체 처리와 일치 확인
P 문제

1시간 단위 종가에 바로 체결됐다고 가정하면 수수료, 호가 차이, 지정가 주문이 체결되지 않는 경우가 빠져 실제와 결과가 다릅니다.

A 분석
  • 시장가 주문: 수수료 0.06%, 제외
  • 지정가 주문: 수수료 0.02%, 체결 여부를 가격 흐름으로 판정
  • 5.25년치 3분 단위 데이터: 월 단위로 나눠 처리하되 한 번에 처리한 결과와 같아야 함
A 실행
  • 주문 후 3분 단위 가격 10개(30분) 동안 지정가를 지나간 만큼만 체결
  • 월 단위로 읽으며 보유 수량과 대기 주문을 다음 달로 이어감
  • 월 단위 결과와 전체 처리 결과가 같은지 테스트로 확인
R 결과

지정가 중심 매매를 계좌 시뮬레이션 기본값으로 채택. 월 단위 처리가 전체 처리와 같은 결과임을 테스트로 확인.

CASE 03Crypto Pilot개인

반복 시험으로 생기는 착시, 시험 횟수 기록과 샤프지수 보정

  1. 후보 시험매번 기록 남김
  2. 횟수 반영시험 기록 52줄
  3. 보정값 판정0.95 이상만
  4. 승격 기록통과 판정 저장
  5. 확인용 데이터07-01 이후 분리
P 문제

전략 후보를 계속 바꿔 시험하면 우연히 좋게 나온 결과를 고르게 됩니다. 시험 횟수만큼 성과를 깎아 봐야 합니다.

A 분석
  • 최종 결과 하나만 보고 판단: 시도 횟수가 가려져 제외
  • 시험 횟수만큼 샤프지수를 깎는 보정값을 승격 기준으로 채택
  • 설계용 데이터와 마지막에 따로 남겨 둔 확인용 데이터 분리
A 실행
  • 시험마다 기록(52줄), 보정값 계산의 시도 횟수로 반영
  • 보정값 0.95 이상만 승격 기록 파일에 올리고 기준값과 판정 기록
  • 설계용 데이터는 2026-07-01까지, 이후는 확인용으로 분리
R 결과

기준값 0.95를 넘어 통과 판정을 기록. 확인용 구간까지 넣은 연평균 수익률 +212.7%로 설계 구간 +220.4%와 비슷. 확인용 구간은 3개월로 짧음. 백테스트

CASE 04Crypto Pilot개인

주문 시각과 겹치지 않는 무중단 업데이트

  1. 코드 변경수집 코드 수정
  2. 변경 비교정규화한 코드 비교
  3. 대기 확인주문 시각·실행 중 여부
  4. 새 버전 교체두 벌 번갈아
P 문제

정해진 주문 시각 전후에 프로그램을 업데이트하면 주문이 늦어지거나 시세 수집이 끊길 수 있습니다.

A 분석
  • 프로그램 재시작: 실시간 연결이 끊겨 데이터가 비어 제외
  • 사람이 시각을 피해 직접 업데이트: 실수 가능, 제외
  • 코드가 바뀐 때만 교체하고 주문 시각 전후엔 자동으로 기다리는 규칙 선택
A 실행
  • 수집 프로그램을 두 벌 띄워 새 버전으로 번갈아 교체
  • 수집 코드를 공백·주석 차이를 없앤 형태로 비교해 실제 변경 여부 판단
  • 주문 결정 시각 전후이거나 자동 매매가 실행 중이면 업데이트 대기
R 결과

변경 판단과 대기 조건을 단위 테스트로 검증. 업데이트 중 끊김 시간 실측치는 없음.

한계

  • 모든 수익률은 재현 시뮬레이션, 실제 운용 결과 아님. 자동 매매는 모의 모드.
  • 평균 배율 약 3.8배, 최대 낙폭 -51%로 실제 운용에서 버티기 어려움.
  • 펀딩 손익의 약 91%가 상위 5개 종목에 집중, 확인용 구간은 3개월.
