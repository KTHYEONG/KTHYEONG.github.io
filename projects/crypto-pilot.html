Crypto Pilot

바이낸스 선물 전략 검증과 모의 자동 매매

개요

바이낸스 무기한 선물의 백테스트부터 24시간 모의 자동 매매까지 한 저장소로 만들었습니다. 기본 전략의 과거 데이터 재현은 연평균 +212.7%, 최대 낙폭 -51.2%, 강제청산 0회였습니다(2026-10-10 실행). 11월에는 머신러닝 보정(ML 보정)을 사전 등록 홀드아웃으로 검증해 모의 데몬에 넣었습니다. 미래 정보 사용, 체결 비용, 강제청산(담보 부족으로 포지션이 강제 정리되는 일), 반복 시험으로 생기는 착시를 줄였습니다. 자동 매매는 모의 모드이며 모든 수익률은 재현 시뮬레이션입니다.

CASE 01Crypto Pilot개인

청산 규칙을 반영한 레버리지 결정

성장 정책은 연평균 수익률이 +139%로 고정 배율(+253~277%)보다 낮지만 최대 낙폭이 -35.0%로 가장 작고 증거금 한도 위반이 없었습니다.
P 문제

빌린 돈으로 배율을 높이면 수익은 커 보여도, 급락해 담보금이 모자라면 포지션이 강제로 정리됩니다. 비중만 계산하는 백테스트는 이를 알 수 없습니다.

배율 방식 비교 (71,000 USDT 계좌, ML 보정 적용, 2022-07 ~ 2026-10, 지정가, 재현 시뮬레이션)

A 분석
  • 전체 기간 수익을 보고 고정 배율을 고르면 미래 정보를 쓴 셈이라 제외
  • 그날까지의 수익 분포만으로 매일 배율을 다시 계산하는 성장 정책 선택
A 실행

  • 강제청산 기준 담보금 구간, 펀딩비, 수수료, 최소 주문 단위를 계좌 시뮬레이터에 반영

CASE 02Crypto Pilot개인

3분 단위 지정가 체결 재현

지정가를 계좌 시뮬레이션의 기본 체결 모델로 채택했고(수수료 6bp→2bp), 구간 분할 처리가 전체 처리와 같은 결과임을 합성 데이터 테스트로 확인했습니다.
  1. 주문 발생지정가 주문
  2. 3분 단위 추적30분 구간
  3. 체결 판정지나간 만큼만
  4. 구간 이어가기보유·대기 주문
  5. 결과 비교전체 처리와 일치 확인
P 문제

1시간 단위 종가에 바로 체결됐다고 가정하면 수수료, 호가 차이, 지정가 주문이 체결되지 않는 경우가 빠져 실제와 결과가 다릅니다.

A 분석
  • 지정가는 수수료가 낮은 대신 체결 여부를 가격 흐름으로 판정해야 함
A 실행
  • 주문 후 3분봉 10개 동안 지정가를 지나간 만큼만 체결
  • 메모리 예산에 맞춰 구간으로 나눠 읽으며 보유 수량과 대기 주문을 이어가고, 한 번에 처리한 결과와 같은지 합성 데이터로 테스트
R 결과

지정가를 계좌 시뮬레이션의 기본 체결 모델로 채택했고(수수료 6bp→2bp), 구간 분할 처리가 전체 처리와 같은 결과임을 합성 데이터 테스트로 확인했습니다.

  • 6bp → 2bp시장가와 지정가 수수료
  • 3분봉 10개주문 후 지정가 체결을 기다리는 시간(30분)
  • 약 96.5%모델이 가정한 지정가 체결 비율(11-08 ML 보정 적용 재실행)
CASE 03Crypto Pilot개인

시험 횟수를 반영한 성과 보정

시도 128회를 반영한 보정값 0.9988로 기준 0.95를 넘었고, 확인용 구간을 포함한 연평균 수익률은 +212.7%로 설계 구간 +220.4%와 비슷합니다.
P 문제

전략 후보를 계속 바꿔 시험하면 우연히 좋게 나온 결과를 고르게 됩니다. 시험 횟수만큼 성과를 깎아 봐야 합니다.

  • 128회보정에 쓴 시도 횟수: 사전 탐색 96 + 고유 시험 기록 32
  • 0.9988보정 샤프지수(DSR), 승격 기준 0.95
  • 54줄시험 기록, 이 중 18줄은 테스트용 합성 데이터라 무효 처리
  • 92일마지막에 따로 남겨 둔 확인용 구간
  1. 10.10설계용 데이터는 2026-07-01까지, 이후는 확인용으로 분리
  2. 10.10평가 기준을 복리 성장·생존 중심으로 전환한 날, 설계 구간 연평균 수익률 시험값이 22.5%~226.8%로 흔들렸고 전환 뒤 마지막 실행이 220.4%
  3. 10.28확인용 구간 1회 조회 제한을 자동 기록과 로직 변경 검사로 대체, 조회 기록은 6건
A 실행
  • 시험마다 기록하고 보정값 계산의 시도 횟수로 반영, 보정값 0.95 이상만 승격 기록 파일에 판정 기록
R 결과

시도 128회를 반영한 보정값 0.9988로 기준 0.95를 넘었고, 확인용 구간을 포함한 연평균 수익률은 +212.7%로 설계 구간 +220.4%와 비슷합니다. 백테스트

CASE 04Crypto Pilot개인

ML 보정의 사전 등록 검증

약 84개 구성 중 사전 등록한 후보 하나가 홀드아웃(119일)의 판정 기준 4개를 모두 통과했고, 이를 모의 데몬에 통합했습니다.
P 문제

머신러닝을 전략에 넣으면 좋아 보이는 설정을 고르기 쉽습니다. 시험을 많이 한 뒤 통과한 결과는 우연일 수 있어, 판정 기준을 먼저 고정해야 합니다.

  1. 시험ML을 넣는 지점별로 약 84개 구성을 시험해 대부분 기각, 시험 횟수 자체를 기록
  2. 사전 등록남은 후보 하나와 판정 기준 4개(절대 성과, 기본 전략 대비 비열등, 낙폭, 신호 상관)를 홀드아웃을 보기 전에 기록
  3. 판정홀드아웃 119일에서 기준 4개를 모두 통과, 표본이 짧아 검정력은 낮다고 기록
  4. 통합모의 데몬에 모델 파일 검증, 재학습 시한 경고, 모델이 바뀌면 기록을 막는 장치와 함께 적용
  5. 게이트실계좌 전환은 사람이 병합한 승인 블록이 데몬 설정과 일치할 때만 허용, 없으면 시작 거부
R 결과

약 84개 구성 중 사전 등록한 후보 하나가 홀드아웃(119일)의 판정 기준 4개를 모두 통과했고, 이를 모의 데몬에 통합했습니다. 실계좌 전환은 사람 승인 게이트 뒤에만 가능합니다. 백테스트

CASE 05Crypto Pilot개인

24시간 운영 결함의 원인 기록

각 결함의 원인을 커밋에 남기고 수정했으며, 대형 일자 처리의 메모리는 2.7GB에서 0.4GB 이하로 줄었습니다.
P 문제

수집·감시·통신을 24시간 돌리면 백테스트에서는 안 보이던 결함이 나옵니다. 조용히 틀린 기록이 남는 결함이 가장 위험했습니다.

  1. 10.16IP 차단(418) 응답 때 차단 해제 시각을 읽어 재시도가 그 시각까지 기다리도록 수정
  2. 10.16설정 요청의 성공 응답을 오류로 처리하던 문제 수정
  3. 10.27대형 일자(785만 행)를 통째로 파싱해 메모리가 2.7GB까지 늘고 3GB 한도 컨테이너가 종료되던 문제를 블록 단위 처리로 0.4GB 이하로 제한
  4. 10.30체결 패리티(내 기록과 거래소 체결의 일치) 감시가 거래 자료 없는 날을 정상(0건)으로 기록하던 문제 수정, 빈 날은 건너뛰고 최근 3일을 다시 점검
A 실행
  • 새 수집 슬롯(실행 한 벌)이 준비된 뒤에 옛 슬롯을 내리는 교체 방식, 배포는 데몬이 쉬는 시간에만 진행하는 게이트
R 결과

각 결함의 원인을 커밋에 남기고 수정했으며, 대형 일자 처리의 메모리는 2.7GB에서 0.4GB 이하로 줄었습니다. 운영 기록

한계

  • 해석 주의
    모든 수익률은 재현 시뮬레이션실제 운용 결과가 아니며 자동 매매는 모의 모드이고, 설계 구간 평균 배율 약 3.8배·낙폭 -51%는 버티기 어렵습니다.
  • 해석 주의
    표본 안 조정 가능성확인용 구간은 92일에 조회 6건이고, 평가 기준을 바꾼 날 시험값이 22.5%~226.8%로 흔들렸으며 시도는 128회입니다.
  • 해석 주의
    자본 증가와 종목 집중자본이 커지면 수익이 줄고(1천 달러 +239.6% → 1천만 달러 +22.0%, ML 보정 재실행) 펀딩 손익 88~93%가 상위 5개 종목에 몰립니다.
  • 미검증
    ML 보정의 낮은 검정력119일 홀드아웃을 사전 등록 시험에 한 번 쓴 통과라 검정력이 낮고 약 84개 시험의 편향이 남으며, 결함 메모리 수치는 커밋 기록 기준입니다.
