SaveTax

시중가보다 비싼 납품 물품을 찾는 감사 도구

사례

CASE 01SaveTax개인

중복 주문 합계 보정, 데이터가 어긋나면 중단

  1. 불러오기데이터 파일 직접 조회
  2. 정합성 검사주문별 내용 일치 확인
  3. 불일치 중단오류로 멈춤
  4. 정리된 조회 화면주문당 1건
  5. 집계빈 값은 0 아님
P 문제

같은 주문이 여러 물품 행에 반복돼 단순 합계가 부풀려집니다. 집계가 틀리면 이후 비싼 집행 판정이 모두 어긋납니다.

A 분석
  • 합계 전 중복 제거 필요
  • 계약번호·금액이 다르면 같은 주문으로 합치지 않음
  • 주문 없는 물품(약 71%)은 0이 아닌 빈 값, 0 채움은 평균 왜곡으로 제외
  • 어긋난 데이터는 넘기지 않고 불러오는 시점에 중단하기로 선택
A 실행
  • DuckDB로 원본 데이터 파일을 바로 조회, 주문별로 내용 일치 검사
  • 주문당 1건으로 정리한 조회 화면 생성, 불일치 시 오류로 중단
  • 빈 값은 0으로 바꾸지 않고 빈 값으로 유지
R 결과

주문당 1건으로 집계하고 불일치 데이터는 중단. 약 24%는 중복 합산 시 부풀려지는 정도로, 대회 안내 수치.

CASE 02SaveTax개인

전용 품목은 부품 가격을 더해 비교하고 출처 기록

  1. 사양 정리CPU·메모리·SSD
  2. 부품 가격쇼핑몰 2곳 근거
  3. 공임 가산표준품셈 적용
  4. 합산 원가기준가 산출
  5. 제보 본문출처·합산식 기재
P 문제

PC, 패치패널, 서버랙은 납품용 전용 모델이라 쇼핑몰에 같은 제품이 없습니다. 시중가 비교로는 후보에서 빠집니다.

A 분석
  • 동급 사양 부품의 가격 합계로 대신 비교
  • 근거가 약해 보일 수 있어 쇼핑몰·페이지 출처를 제보에 적음
  • 근거 종류별 신뢰도가 달라 4종으로 나누고 기준 배율도 분리
A 실행
  • 사양 정리 후 시판 부품 가격 합산, 설치 품목은 표준품셈 공임 가산
  • 부품별 쇼핑몰 2곳 근거, 1.2~1.3배 구간은 두 번째 가격으로 재확인
  • 기준 배율(쇼핑몰 비교 1.10, 나머지 3종 1.20)을 설정 한곳에 모음
R 결과

부품 구성 정의 32개, 쇼핑몰 검색 규칙 18곳. 제보 본문에 출처와 합산식 포함.

CASE 03SaveTax개인

옵션이 섞인 계약에서 잘못된 후보를 줄이는 기준

  1. 옵션 확인단가가 여럿인지
  2. 대표 단가가장 높은 값
  3. 계열 분리다른 블록은 비교 안 함
  4. 시점 검증납품일에 유효한지
P 문제

단가가 다른 옵션이 섞인 계약에서 비싼 본품을 싼 옵션과 비교해, 실제로는 정상인 건이 후보로 잡힙니다.

A 분석
  • 평균·최저 단가 기준은 과다 집행처럼 보이는 후보가 늘어 제외
  • 가장 높은 대표 단가 기준은 후보가 줄고 제보 횟수 한도에 맞아 선택
  • 비교 단가의 납품일 유효 여부 별도 확인
A 실행
  • 옵션이 여러 개면 가장 높은 대표 단가를 기준으로 사용
  • 계약 내 품목 묶음이 다른 계열(일반형·내진형)은 비교 제외
  • 변경계약일·납품 이력으로 단가가 유효한 시점 확인
R 결과

후보를 적게 내는 방향으로 설계, 기준마다 자동 테스트 작성.

CASE 04SaveTax개인

다시 실행해도 같은 건은 두 번 제출되지 않음

  1. 사람 승인내용 해시에 묶음
  2. 가격 재확인제출 직전
  3. 제출 기록전송 전에 먼저
  4. 전송고유 번호 포함
  5. 재실행 확인결과 미확인 건 서버 조회
P 문제

제보 횟수에 한도가 있어, 프로그램을 다시 실행하면 같은 건이 두 번 제출되고 횟수가 이중으로 차감될 수 있습니다. 인증 정보 유출도 막아야 합니다.

A 분석
  • 전송 후 기록: '보냈는데 기록 없음' 상태가 생기면 복구 불가
  • 전송 전 기록: 다시 실행할 때 서버 조회로 확인할 수 있어 선택
  • 승인은 사람이 하고, 내용이 바뀌면 무효가 되도록 내용과 묶음
A 실행
  • 요청 고유 번호를 제출 기록 파일에 먼저 기록(동시 접근 잠금, 디스크 반영 확인), 재실행 시 결과 미확인 건 점검
  • 승인을 제출 내용의 지문값에 묶고, 제출 직전 가격 재확인
  • 인증 정보는 공식 주소로만 전송, 다른 주소로 넘어가는 것 차단, 로그에서 가림
R 결과

다시 실행해도 같은 건을 다시 보내지 않는 구조. 해당 경로는 자동 테스트 있음.

한계

  • 원본 데이터와 참가자 인증 정보가 저장소에 없어 전체 실행 재현 불가, 테스트는 합성 데이터.
  • 과다 집행 판정은 시중가 비교 추정, 심사에서 근거 부족일 수 있음.
  • 제출 건수·금액은 내 제출 기록 파일 기준(저장소 미포함), 심사 인정액과 다를 수 있음.
  • 대회 결과는 확정 전이라 싣지 않음.
