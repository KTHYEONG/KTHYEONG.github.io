SaveTax

시중가보다 비싼 납품 물품을 찾아 근거와 함께 제보하는 분석 도구

개요

공공조달 자료에서 시중가보다 비싼 집행을 찾아, 중복 주문 정리와 사람 승인 뒤 제출 흐름으로 안전하게 제보했습니다. 잠정 판정의 반려 건에는 이의로 대응해 참가자 1,169명 중 45위로 마쳤습니다.

CASE 02SaveTax개인

제출 장부로 재실행해도 이중 제출되지 않게 방지

다시 실행해도 같은 건을 다시 보내지 않는 구조입니다.
  1. 사람 승인내용 해시에 묶음
  2. 가격 재확인제출 직전
  3. 제출 기록전송 전에 먼저
  4. 전송고유 번호 포함
  5. 재실행 확인결과 미확인 건 서버 조회
P 문제

제보 횟수에 한도가 있어, 프로그램을 다시 실행하면 같은 건이 두 번 제출되고 횟수가 이중으로 차감될 수 있습니다. 인증 정보 유출도 막아야 합니다.

기록 시점 비교
전송 후에 기록전송 전에 기록 선택
장애 시 상태'보냈는데 기록 없음''기록은 있는데 보냈는지 모름'
복구서버에 무엇이 갔는지 알 수 없어 불가재실행 때 고유 번호로 서버에 조회해 확인
결과횟수 한도가 이중으로 차감될 수 있음같은 건을 다시 보내지 않음
A 실행
  • 요청 고유 번호를 제출 기록 파일에 먼저 기록(동시 접근 잠금, 디스크 반영 확인), 재실행 시 결과 미확인 건 점검
  • 승인은 사람이 하고 제출 내용의 지문값에 묶어 내용이 바뀌면 무효, 제출 직전 가격 재확인
  • 인증 정보는 공식 주소로만 전송, 다른 주소로 넘어가는 것 차단, 로그에서 가림
R 결과

다시 실행해도 같은 건을 다시 보내지 않는 구조입니다. 제출기 48개를 포함한 원장·승인·HTTP 테스트 약 90개가 재시도, 결과 미확인 건의 중단, 중복 물품 재전송 방지를 확인하고, 실제 운영에서도 전송 전에 509회 차단했습니다. 운영 기록

CASE 03SaveTax개인

중복 주문 합계를 보정하고 불일치 시 중단

중복 제거 전후 합계 차이가 23.9%로, 대회 안내의 '약 24%'를 공식 데이터로 직접 재현했습니다.
P 문제

같은 주문이 여러 물품 행에 반복돼 단순 합계가 부풀려집니다. 집계가 틀리면 이후 비싼 집행 판정이 모두 어긋납니다.

  • 1,052,815물품 등재 행, 이 중 29.3%만 주문이 있고 나머지는 빈 값
  • 300,431주문(납품 키), 5,975개는 여러 등재가 공유(최대 18곳)
  • 21.76조 → 17.57조중복 제거 전후 납품요구 금액 합계, 제거 전이 23.9% 큼
  • 0건금액·물품이 어긋난 주문(공식 데이터 r5 기준)
A 분석
  • 합계 전 주문 단위로 중복을 제거하고, 계약번호·금액이 다르면 같은 주문으로 합치지 않음
  • 주문 없는 물품은 0이 아닌 빈 값, 0 채움은 평균 왜곡으로 제외
A 실행
  • DuckDB로 원본 데이터 파일을 바로 조회, 주문별로 내용 일치 검사
  • 주문당 1건으로 정리한 조회 화면 생성, 불일치 시 불러오는 시점에 오류로 중단
R 결과

중복 제거 전후 합계 차이가 23.9%로, 대회 안내의 '약 24%'를 공식 데이터로 직접 재현했습니다. 이 데이터 버전(r5)에서는 어긋난 주문이 없어 중단이 발동하지 않았지만, 데이터가 바뀌어도 틀린 합계가 조용히 나오지 않게 하는 안전장치입니다. 운영 기록

CASE 04SaveTax개인

부품 가격 합산 비교로 전용 모델 납품 물품 검토

랙은 잠정 판정에서 인정이 나왔고(품목 표 참고), 데스크톱은 반려가 많아 이의로 대응했습니다.
  1. 사양 정리CPU·메모리·SSD
  2. 부품 가격쇼핑몰 2곳 근거
  3. 공임 가산표준품셈 적용
  4. 합산 원가기준가 산출
  5. 제보 본문출처·합산식 기재
P 문제

PC, 패치패널, 서버랙은 납품용 전용 모델이라 쇼핑몰에 같은 제품이 없습니다. 시중가 비교로는 후보에서 빠집니다.

A 분석
  • 동급 사양 부품의 가격 합계로 대신 비교, 근거가 약해 보일 수 있어 쇼핑몰·페이지 출처를 제보에 적음
  • 근거 종류별 신뢰도가 달라 종류를 나누고 기준 배율도 분리
  • 같은 물품의 다른 계약 단가는 시중가로 인정되지 않음(물탱크 44건 중 38건 접수 중 반려), 이후 쇼핑몰 기반으로 전환
A 실행
  • 사양 정리 후 시판 부품 가격 합산, 설치 품목은 표준품셈 공임 가산
  • 부품별 쇼핑몰 2곳 근거, 1.2~1.3배 구간은 두 번째 가격으로 재확인
  • 기준 배율(쇼핑몰 비교 1.10, 나머지 3종 1.20)을 설정 한곳에 모음
R 결과

랙은 잠정 판정에서 인정이 나왔고(품목 표 참고), 데스크톱은 반려가 많아 이의로 대응했습니다. 부품 구성 정의 32개와 쇼핑몰 검색 규칙 18곳으로 제보 본문에 출처와 합산식을 넣었습니다. 운영 기록

한계

  • 해석 주의
    판정은 시중가 비교 추정심사에서 근거 부족일 수 있어 접수 금액보다 확정액이 낮았습니다(결과 카드 참고, 최초 제출 시 금액은 13.7억 원).
  • 해석 주의
    이의 효과를 분리하지 못함건별 이의 결과가 공개되지 않아 인정액 상승에서 이의 효과와 잠정 때 비공개였던 65건의 영향을 나눌 수 없습니다.
  • 배운 점
    근거 종류의 사전 점검이 늦었음먼저 등록한 사람이 갖는 대회라 139건 중 106건을 첫 이틀에 냈지만, 데스크톱·랙 반려 사유(판매 페이지 아님, 52건 전부)는 마감 뒤(10.30)에야 알았고 근거 종류의 인정 여부를 첫 제출 전에 점검했어야 했습니다.
  • 해석 주의
    제출 수치의 기준제출 117건(철회 22건 제외, 운영진 반려 39건 포함)과 접수 금액은 내 제출 기록 기준, 확정액·순위는 공식 결과 기준이며 테스트는 합성 데이터입니다.
