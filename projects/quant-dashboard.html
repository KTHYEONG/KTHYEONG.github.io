Quant Dashboard

수집 작업 정상 여부를 읽기만 하는 상태판

개요

한 서버의 퀀트 수집 작업이 오늘 제때 돌았는지, 접속 없이 한 화면에서 봅니다. systemd, Docker, 프로젝트 파일을 읽기만 해 OK / WARN / UNKNOWN / FAIL로 판정하며, 감시 대상에 영향을 주지 않는 것이 핵심 요구사항입니다.

CASE 01Quant Dashboard개인

날짜 분류를 판정 앞단에, 정상 공백은 장애 제외

  1. 날짜 분류5가지 중 하나로 분류
  2. 할 일 결정일정표와 비교
  3. 시간대 판정정규장·동시호가·애프터
  4. 단계 부여OK/WARN/FAIL
  5. 미확인 처리범위 밖은 UNKNOWN
P 문제

같은 '데이터 없음'도 장중이면 장애, 휴장일·동시호가면 정상입니다. 개발 중 오탐이 세 번 났습니다(커밋 이력).

A 분석
  • 시간대별 임계값만 두는 방식 제외: 날짜를 모르면 할 일을 못 정함
  • 거래일·휴장일·주말·시간 변경일·미확인으로 먼저 분류
  • 정규장 틱 120초 WARN, 300초 FAIL, 15:20~15:40 보류
A 실행
  • 달력 5분류 모듈 작성, 2026년 밖은 UNKNOWN
  • 휴장일 정상 종료 작업은 결측 아닌 정상 종료로 표시
  • 달력 분류·시간대 판정 단위 테스트로 고정
R 결과 코드로 확인

휴장일·동시호가·마감 후처리 하트비트 단절, 오탐 세 가지 수정 후 테스트 고정. 오탐 감소량은 측정하지 않음.

CASE 02Quant Dashboard개인

명령 자체를 막는 읽기 전용, 파일은 수정 시각만

  1. 명령 요청외부 명령은 한 곳으로
  2. 허용 목록읽기 명령만 통과
  3. 수정 시각파일 내용은 안 읽음
  4. 자원 상한128MB
P 문제

대시보드가 서비스를 건드리거나 틱 파일을 읽으면, 수집을 지키는 도구가 수집을 방해합니다.

A 분석
  • 명령을 허용하고 조심하는 방식 제외: 코드 변경 시 깨질 수 있음
  • 외부 명령을 한 곳에 모으고 허용 목록만 통과
  • 수집 지속 여부는 최신 파일 수정 시각으로 충분
A 실행
  • systemctl show, is-active, list-timers만 허용, 나머지 예외
  • os.scandir로 수정 시각만 조회, 심볼릭 링크 미추적
  • 이벤트 로그는 끝에서 최대 2MiB만 읽기
  • 수집기 128MB·CPU 25% 상한, 배포는 감시 유닛 5종만 등록
R 결과 코드로 확인

코드 기준 틱 파일 내용은 읽지 않고, 대상 서비스를 바꿀 수 없는 구조. 자원 상한은 설정값이며 실측 아님.

한계

  • 휴장일 달력은 직접 입력한 2026년 값
  • 오탐·미탐 정량 평가 없음, 알림 기능 없음
