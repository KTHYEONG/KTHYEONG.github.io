Quant Dashboard

수집 작업 정상 여부를 읽기만 하는 상태판

개요

한 서버의 퀀트 수집 작업이 오늘 제때 돌았는지, 접속 없이 한 화면에서 봅니다. 서비스 관리 도구(systemd), Docker, 프로젝트 파일을 읽기만 해 정상 / 주의 / 확인 불가 / 장애로 판정하며, 감시 대상에 영향을 주지 않는 것이 핵심 요구사항입니다.

CASE 01Quant Dashboard개인

먼저 날짜 종류를 분류해, 정상적인 공백은 장애로 보지 않음

  1. 날짜 분류5가지 중 하나로 분류
  2. 할 일 결정일정표와 비교
  3. 시간대 판정정규장·동시호가·애프터
  4. 단계 부여정상·주의·장애
  5. 미확인 처리범위 밖은 확인 불가
P 문제

같은 '데이터 없음'도 장중이면 장애, 휴장일이나 동시호가(장 시작·마감 전 주문만 받는 시간)면 정상입니다. 개발 중 잘못된 경보가 세 번 났습니다.

A 분석
  • 시간대별 임계값만 두는 방식 제외: 날짜를 모르면 할 일을 못 정함
  • 거래일·휴장일·주말·시간 변경일·미확인으로 먼저 분류
  • 정규장에서 틱이 120초 끊기면 주의, 300초면 장애, 15:20~15:40은 판정 보류
A 실행
  • 날짜를 5가지로 나누는 모듈 작성, 2026년 밖은 확인 불가 처리
  • 휴장일에 정상 종료된 작업은 누락이 아닌 정상 종료로 표시
  • 날짜 분류·시간대 판정을 자동 테스트로 고정
R 결과

휴장일, 동시호가, 마감 후 처리 중 생존 신호 끊김, 잘못된 경보 세 가지를 고치고 테스트로 고정. 경보 감소량은 측정하지 않음.

CASE 02Quant Dashboard개인

읽기 명령만 허용하는 구조, 파일은 수정 시각만 확인

  1. 명령 요청외부 명령은 한 곳으로
  2. 허용 목록읽기 명령만 통과
  3. 수정 시각파일 내용은 안 읽음
  4. 자원 상한메모리 128MB·CPU 25%
P 문제

대시보드가 서비스를 건드리거나 틱 파일을 읽으면, 수집을 지키는 도구가 수집을 방해합니다.

A 분석
  • 아무 명령이나 허용하고 조심해서 쓰는 방식: 코드가 바뀌면 깨질 수 있어 제외
  • 외부 명령 실행을 한 곳에 모으고 허용 목록에 있는 것만 통과
  • 수집이 계속되는지는 최신 파일의 수정 시각만으로 충분
A 실행
  • 서비스 상태 조회 명령 3가지만 허용, 나머지는 실행 거부
  • 파일 목록에서 수정 시각만 조회, 바로가기 파일은 따라가지 않음
  • 이벤트 기록은 끝에서 최대 2MB만 읽기
  • 상태 수집기에 메모리 128MB·CPU 25% 상한, 배포 시 감시용 서비스 5종만 등록
R 결과

코드 기준 틱 파일 내용은 읽지 않고, 대상 서비스를 바꿀 수 없는 구조. 자원 상한은 설정값이며 실측 아님.
