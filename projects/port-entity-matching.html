Port Entity Matching

입출항 기록을 표준 선박 한 척으로 잇는 매칭 파이프라인

개요

DACON 항만 문제 해결 AI 대회 과제입니다. 오타·한글 표기·빈 제원이 섞인 입출항 기록 한 줄을 약 7만 8천 척의 표준 선박 중 하나로 연결합니다. 한글 선박명이 점수의 70%라 한글 매칭에 집중했고, 교란 시나리오로 약점을 찾아 고쳤습니다.

CASE 01Port Entity Matching개인

교차검증 0.9875 vs 리더보드 0.8805, 원인 분리

P 문제

로컬 점수와 리더보드 차이가 컸습니다. 원인을 모른 채 모델을 고치면 제출만 낭비합니다.

A 분석
  • 학습·서빙 경로 불일치: 예측 비교 차이 0건, 제외
  • 미학습 선박 0.998, 라틴 톤수 잡음 0.9965, 라틴 오타 0.957: 제외
  • 토큰 순서 변경·누락 시 정확도 0.4~0.5로 하락
  • 학습 데이터는 한 선박이 늘 같은 철자, 교차검증으로 확인 불가
A 실행
  • 깨끗한 교차검증 + 교란 20개 스트레스 스위트 병행
  • 표기 증강 학습 추가
  • 순서 무관 검색(정렬 키, 토큰 색인), 순서 불변 특징 7종 추가
R 결과

스위트 점수 0.8162에서 0.9477, 토큰 순서를 바꾼 라틴 이름 정확도 0.486에서 0.999. 모의 교란 기준이며 실제 테스트 교란 비율은 알 수 없습니다. 백테스트

CASE 02Port Entity Matching개인

한글 선박명, 규칙 소리 키 + LLM 후보로 분담

  1. 정규화이름 정리
  2. 후보 검색소리 키 + 톤수 창
  3. LLM 표기라틴 후보 추가
  4. 랭커LightGBM lambdarank
  5. 재순위한글 상위 10개
  6. 선박 1척vessel_id 확정
P 문제

한글 이름은 차용어·로마자·약어 읽기가 섞여 규칙 하나로 못 맞춥니다. 한글 행은 데이터의 약 9.7%, 점수의 70%입니다.

A 분석
  • 표준 로마자 표기만 사용: 한글 오류 24건에서 63건, 제외
  • 자음·모음 소리 키 채택 + 차용어 규칙(묵음 R, 어두 H, 모음 Y)
  • 한글 오류 23건에서 14건 (5개 시드 평균)
  • 미학습 표기에 약해 LLM 라틴 표기 채널 추가
A 실행
  • 소리 키 + 톤수 창(±25%) 후보에 Kanana 후보 합산
  • LLM은 후보만 확장, 최종 판단은 랭커
  • 한글 행 상위 10개 LLM 우도 재순위
R 결과

리더보드 규칙 v2 0.8805, LLM 후보 채널 0.9163(한글 479/532, 비한글 1701/1784). 표기 증강 LLM 변형은 0.9036이라 되돌렸습니다. 운영 기록

CASE 03Port Entity Matching개인

수식 대신 학습형 랭커 선택, 차이는 불확실로 기록

P 문제

신호가 많고 일부는 비어 있어 수동 가중치로는 결측을 다루기 어렵습니다.

A 분석
  • 수동 가중치 수식 0.9814, 로지스틱 회귀 0.9809: 결측 조합 한계, 제외
  • LightGBM binary 0.9852 vs lambdarank 0.9857, 같은 후보·폴드 비교
  • 후보별 순위를 직접 학습하는 lambdarank 선택
  • CatBoost 등 앙상블: 개선 없음, 미채택
A 실행
  • lambdarank 5개 시드 앙상블
  • 결측값 채우지 않고 모델이 처리
  • 차이의 신뢰구간이 0을 포함함을 문서에 명시
R 결과

5-fold에서 lambdarank 0.9857로 최고지만 차이는 통계적으로 불확실. 선택 이유는 성능 우위가 아닌 결측 처리 편의입니다. 백테스트

CASE 04Port Entity Matching개인

한글 선박 382척, 흔들리는 점수를 통계로 판단

P 문제

한글 선박 1척이 한글 정확도 약 0.25%p를 움직이고, 시드만 바꿔도 한글 오류가 16~19건 달라집니다.

A 분석
  • 단일 실행 비교: 시드 흔들림과 구분 불가, 제외
  • 선박 단위 부트스트랩 95% 신뢰구간 채택
  • 5개 시드 평균, 같은 폴드 짝지은 비교 채택
A 실행
  • 비교 도구(tools/evaluate.py compare) 구현
  • 오류 4건 미만 차이는 해석 금지 기준 문서화
  • 행 독립성(단독·일부·순서 뒤섞기 동일 예측) 테스트로 강제
R 결과

15 leaves, 토큰 정렬 특징, 모델 앙상블 등 불확실한 실험은 미채택.

한계

  • 0.9910은 LLM 채널 추가 전 값, 현재 코드 교차검증은 미측정
  • 대회 진행 중이라 최종 순위 없음
  • 토큰 하나 빠진 이름은 약함(라틴 약 0.69, 한글 약 0.65, 모의 기준)
  • 이름·톤수가 같은 자매선은 외부 DB 없이 구분 어려움
