Port Entity Matching

입출항 기록을 표준 선박 한 척으로 잇는 매칭 파이프라인

개요

DACON 항만 문제 해결 AI 대회 과제입니다. 오타·한글 표기·빈 제원이 섞인 입출항 기록 한 줄을 약 7만 8천 척의 표준 선박 중 하나로 연결합니다. 한글 선박명이 점수의 70%라 한글 매칭에 집중했고, 교란 시나리오로 약점을 찾아 고쳤습니다.

CASE 01Port Entity Matching개인

내부 검증 0.9875 vs 대회 점수 0.8805, 원인 분리

P 문제

내 컴퓨터 검증 점수와 대회 리더보드 점수 차이가 컸습니다. 원인을 모른 채 모델을 고치면 제출만 낭비합니다.

A 분석
  • 학습 때와 제출 때 처리 방식 불일치: 예측 차이 0건, 제외
  • 처음 보는 선박 0.998, 영문 톤수 오차 0.9965, 영문 오타 0.957: 제외
  • 단어 순서를 바꾸거나 단어가 빠지면 정확도 0.4~0.5로 하락
  • 학습 데이터는 한 선박이 늘 같은 철자, 내부 검증으로 확인 불가
A 실행
  • 깨끗한 내부 검증 + 교란 20개 시나리오 점검 병행
  • 표기 증강 학습 추가
  • 단어 순서와 무관한 검색, 순서가 바뀌어도 같은 값인 특징 7종 추가
R 결과

교란 점검 점수 0.8162에서 0.9477, 단어 순서를 바꾼 영문 이름 정확도 0.486에서 0.999. 모의 교란 기준이며 실제 테스트 교란 비율은 알 수 없습니다. 백테스트

CASE 02Port Entity Matching개인

한글 선박명, 발음 규칙과 LLM 후보로 분담

  1. 정규화이름 정리
  2. 후보 검색발음 키 + 톤수 범위
  3. LLM 표기영문 후보 추가
  4. 순위 모델후보별 순위 학습
  5. 재정렬한글 상위 10개
  6. 선박 1척표준 선박 확정
P 문제

한글 이름은 외래어·영문 표기·약어 읽기가 섞여 규칙 하나로 못 맞춥니다. 한글 행은 데이터의 약 9.7%, 점수의 70%입니다.

A 분석
  • 표준 영문 변환만 사용: 한글 오류 24건에서 63건, 제외
  • 자음·모음 발음 키 채택 + 외래어 규칙(발음 안 나는 R, 첫 글자 H, 모음 Y)
  • 한글 오류 23건에서 14건 (5회 학습 평균)
  • 처음 보는 표기에 약해 LLM 영문 표기 후보 추가
A 실행
  • 발음 키 + 톤수 ±25% 후보에 LLM 후보 합산
  • LLM은 후보만 늘리고, 최종 판단은 순위 모델
  • 한글 상위 10개를 LLM 가능성 점수로 재정렬
R 결과

리더보드 규칙 v2 0.8805, LLM 후보 추가 0.9163(한글 479/532, 비한글 1701/1784). 표기 증강 LLM 방식은 0.9036이라 되돌렸습니다. 운영 기록

CASE 03Port Entity Matching개인

수식 대신 학습형 순위 모델 선택, 차이는 불확실로 기록

P 문제

비교 단서가 많고 일부는 비어 있어, 직접 정한 가중치로는 빈 값을 다루기 어렵습니다.

A 분석
  • 직접 정한 가중치 수식 0.9814, 단순 회귀 모델 0.9809: 빈 값 처리 한계, 제외
  • 정답 여부 분류 방식 0.9852 vs 순위 학습 방식 0.9857, 같은 후보·같은 분할로 비교
  • 후보 순위를 직접 학습하는 순위 학습 방식 선택
  • 다른 모델 추가 결합: 개선 없음, 미채택
A 실행
  • 순위 학습 모델을 5회 달리 학습해 결과 합산
  • 빈 값을 채우지 않고 모델이 그대로 처리
  • 차이의 신뢰구간이 0을 포함함을 문서에 명시
R 결과

5분할 검증에서 순위 학습 방식 0.9857로 최고지만 차이는 통계적으로 불확실. 선택 이유는 성능 우위가 아닌 빈 값 처리 편의입니다. 백테스트

CASE 04Port Entity Matching개인

한글 선박 382척, 흔들리는 점수를 통계로 판단

P 문제

한글 선박 1척이 한글 정확도 약 0.25%p를 움직이고, 학습 무작위값만 바꿔도 한글 오류가 16~19건 달라집니다.

A 분석
  • 한 번 실행한 결과 비교: 무작위 흔들림과 구분 불가, 제외
  • 선박 단위 반복 재표본으로 95% 신뢰구간 계산 채택
  • 5회 학습 평균, 같은 분할끼리 짝지어 비교 채택
A 실행
  • 두 실험을 통계로 비교하는 도구 구현
  • 오류 4건 미만 차이는 해석 금지 기준 문서화
  • 기록 한 줄의 예측이 다른 줄과 무관함(단독·일부·순서 뒤섞기 동일 예측)을 테스트로 강제
R 결과

모델 크기 확대, 단어 정렬 특징, 모델 결합 등 효과가 불확실한 실험은 미채택.

한계

  • 0.9910은 LLM 후보 추가 전 값, 현재 코드의 내부 검증은 미측정
  • 대회 진행 중이라 최종 순위 없음
  • 단어 하나 빠진 이름은 약함(영문 약 0.69, 한글 약 0.65, 모의 기준)
  • 이름·톤수가 같은 자매선은 외부 DB 없이 구분 어려움
