Port Entity Matching

입출항 기록을 표준 선박 한 척으로 잇는 매칭 파이프라인

개요

해양수산부 주최 DACON 항만 문제 해결 AI 대회에 개인으로 참가해, 비공개 리더보드 468명 중 106위(0.91989)로 마쳤습니다. 과제는 오타·한글 표기·빈 제원이 섞인 입출항 기록 한 줄을 약 7만 8천 척의 표준 선박 중 하나로 연결하는 것입니다. 한글 선박명이 점수의 70%라 한글 매칭에 집중했고, 발음 코드와 LLM 후보로 시작해 선박 카탈로그의 영문명을 한글로 바꿔 대조하는 역방향 채널까지 넣었습니다.

내 컴퓨터 검증 점수와 대회 리더보드 점수 차이가 컸습니다. 원인을 모른 채 모델을 고치면 제출만 낭비합니다.

CASE 02Port Entity Matching개인

한글 선박명, 발음 코드·LLM 후보·역방향 채널로 분담

P 문제

한글 이름은 영어 외래어, 한국어 로마자, 약어 읽기가 섞여 규칙 하나로 못 맞춥니다. 한글 행은 데이터의 약 9.7%, 점수의 70%입니다.

  1. 1단계공개 0.8805: 규칙 기반 기준선
  2. 2단계0.9163: LLM 영문 표기 후보 추가
  3. 3단계0.9525: 역방향 채널·합성 영문 행 추가(한글 505/532)
  4. 4단계0.9563: 비한글 후보 폭 확대
  5. 5단계0.9595: 최종 제출물(한글 507/532), 비공개 최종 0.91989
한글 선박명 유형 (한글 → 정답 표기)
  • 리플렉션→Reflection영어 외래어
  • 흥아→Heung-A한국어 로마자
  • 에스티아이→STI약어 읽기
A 분석
  • 표준 영문 변환만 쓰면 한글 오류가 24건에서 63건으로 늘어 제외, 발음 코드(자음·모음 소리 기호 + 외래어 보정)는 23건에서 14건(5회 학습 평균)
  • 처음 보는 표기에 약해 LLM 영문 표기 후보를 추가, 역방향 채널은 당시 최고 모델의 한글 오류 41건 중 17건을 해소할 수 있음을 확인
  • 세 번째 한글 표기 생성, 합성 한글 행, 재순위 가중치 상향은 한글 정답 500~504에 머물러 제외
A 실행
  • 발음 코드 + 톤수 범위 후보에 LLM 후보를 합산하고, LLM은 후보만 늘리며 최종 판단은 순위 모델, 한글 상위 10개는 LLM 가능성 점수로 재정렬
  • 카탈로그 영문명을 두 LLM(Midm, Kanana)으로 미리 한글 변환해 두고, 한글 행은 자모 상위 20척을 후보에 합산하고 특징 3개 추가
  • 학습에만 쓰는 변형 6종(이름 잘림, 표기 변형, 톤수 오류, 한글 자모 잡음 등)과 카탈로그 기반 합성 영문 행 15,000개
R 결과

공개 점수가 0.8805에서 0.9595로 올랐습니다. 재학습 오차가 한글 ±2행, 비한글 ±4행이라 한글 3행 이상 개선만 인정했습니다. 단계별 값은 리더보드에서 확인한 공개(테스트 50%) 점수입니다. 운영 기록

CASE 03Port Entity Matching개인

오르지 않는 지점에서 멈추고, 남은 한글 오류 25건의 원인 구분

P 문제

역방향 채널 뒤에도 한글 오류 25건이 남았습니다. 표기를 더 정확히 만들거나 모델을 키우면 줄어드는지 모른 채 시도만 늘리면 제출 횟수만 쓰게 됩니다.

A 분석
  • 더 큰 LLM으로 카탈로그 표기를 다시 만들어 정확도가 62%에서 77%까지 올라도 점수는 그대로였고, 다른 랭커·선박 사전확률·검색 확대도 효과가 없거나 하락(아래 표)
  • 남은 오류는 이름이 거의 같은 자매선 중 어느 배인지 한 행만으로 정할 수 없는 경우가 대부분
  • 같은 호출부호의 다른 기록을 모아 투표하면 한글 오류가 줄어들지만(합성 쌍둥이 평가에서 100건 → 6건, 실제 학습 데이터에서 21건 → 19건), 다른 행을 쓰는 방식이라 대회 규칙상 제외
A 실행
  • 표기·모델·랭커 확대 시도는 중단하고 미채택으로 기록
  • 학습 선박만 답하는 제출로 정답이 0임을 확인한 뒤, 호출부호 일치 없이 1위가 학습 선박이면 다음 학습 밖 후보로 교체(대회 분할 구조를 이용한 규칙임을 문서에 명시)
  • 비한글 행의 후보 폭 확대와 학습 데이터의 단어 대응표·약어 읽기로 만든 표기 추가
R 결과

한글 정답이 505에서 507로, 점수가 0.9525에서 0.9595로 올랐습니다(후보 폭 확대 0.9563, 학습 선박 제외 0.9581). 이후 시도는 모두 효과가 없었습니다. 운영 기록

리더보드로 확인한 시도 (한글 정답 수 변화)
  • 더 큰 LLM 표기→0 ~ −1표기 정확도 62→77%
  • CatBoost 랭커→−3랭커 종류는 병목 아님
  • 선박 사전확률→−4비한글도 13행 하락
  • 검색·재순위 확대→0후보 범위는 병목 아님
CASE 04Port Entity Matching개인

수식 대신 학습형 순위 모델 선택, 차이는 통계적으로 불확실

P 문제

비교 단서가 많고 일부는 비어 있어 직접 정한 가중치로는 빈 값을 다루기 어렵습니다. 한글 선박은 382척뿐이라 점수도 쉽게 흔들립니다.

  • 382척한글 선박 수, 1척이 한글 정확도 약 0.25%p를 움직임
  • 16~19건학습 무작위값만 바꿔도 달라지는 한글 오류 수
  • 4건 미만차이를 해석하지 않기로 문서화한 기준
같은 후보·같은 분할에서 비교한 5분할 가중 점수
직접 정한 가중치 수식단순 회귀정답 여부 분류순위 학습 선택
점수0.98140.98090.98520.9857
판단빈 값 처리 한계빈 값 처리 한계차이 불확실선택
A 실행
  • 순위 학습 모델을 5회 달리 학습해 합산하고, 빈 값은 채우지 않고 모델이 그대로 처리
  • 선박 단위 반복 재표본 95% 신뢰구간과 5회 평균·같은 분할 짝 비교로 두 실험을 통계로 비교하는 도구 구현
  • 기록 한 줄의 예측이 다른 줄과 무관함(단독·일부·순서 뒤섞기 동일 예측)을 테스트로 강제
R 결과

순위 학습 방식이 0.9857로 최고지만 수식 대비 차이는 통계적으로 불확실합니다. 선택 이유는 성능 우위가 아니라 빈 값을 그대로 처리하는 편의입니다. 효과가 불확실한 모델 크기 확대·모델 결합 등은 미채택했습니다. 백테스트

한계

  • 공개 0.9595가 비공개 0.91989로 약 0.04 낮아진 원인과 내부 검증–리더보드 차이를 끝까지 설명하지 못함, 내 컴퓨터의 모의 오류로는 리더보드의 한글 오류가 재현되지 않음
  • 점수 개선 여부를 공개 리더보드(테스트 50%)로 반복 확인했고, 비공개 하락과의 관계는 확인하지 못함. 정답 집합을 추정하는 분석 도구(evaluation/lb)는 개발 전용으로 제출 코드에서 쓰지 않음
  • 규칙 해석 위험: 역방향 채널(카탈로그 이름을 미리 한글로 변환)은 허용 여부를 운영진에게 직접 확인받지 못했고(공식 답변은 학습 데이터 기반 LLM 증강까지, 생성 코드·프롬프트는 보관), 학습 선박 제외는 대회 분할 구조를 이용한 규칙으로 현장에서는 호출부호 기억이 그 역할
  • 서버(L4)에서 실측하지 않아 추론 시간 약 16분은 로컬 측정에서 낸 추정치
  • 단어 하나 빠진 이름은 약함(영문 약 0.69, 한글 약 0.65, 모의 기준), 이름·톤수가 같은 자매선은 한 행만으로 구분 어려움
  • 대회 데이터 재배포 금지로 저장소만으로는 학습·평가 재현 불가
