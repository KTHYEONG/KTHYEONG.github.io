KRX-Alpha

호가·체결 틱 수집·검증 데이터 파이프라인

개요

증권사 실시간 API는 끊긴 구간의 체결을 다시 보내 주지 않습니다. 알파 연구 전에 틱 수집, 누락 보충, 모의 주문 검증 인프라를 먼저 만들었습니다. 알파 연구는 시작 전입니다.

사례

CASE 01KRX-Alpha개인

장중에는 원본만 기록, 파싱은 장 마감 후

  1. 수신WebSocket 메시지
  2. 원본 기록recv_ts만 붙임
  3. L0 보관jsonl.zst 이어쓰기
  4. 장마감 후파싱·중복 제거
  5. L1 변환Parquet + 품질 검사
P 문제

개장 직후 메시지가 몰립니다. 수신 중 파싱하면 처리가 밀려 놓칠 수 있습니다.

A 분석
  • 수신 즉시 정제: 단순하나 파싱 오류가 곧 손실이라 제외
  • 원본 먼저 기록: 규칙을 고쳐도 재계산 가능해 선택
A 실행
  • 수신 경로: recv_ts만 붙여 .jsonl.zst에 이어쓰기
  • 파싱·중복 제거·품질 검사: 장마감 후 L0→L1 Parquet으로 분리
R 결과

수신 경로와 해석 단계를 코드상 분리. 실제 손실률은 측정하지 않음.

CASE 02KRX-Alpha개인

끊긴 구간, 체결 순번으로 찾아 타사 API로 보충

  1. 순번 감사종목별 빈틈 계산
  2. 구간 확정시간대·종목 특정
  3. 타사 보충키움·KIS 체결 이력
  4. 병합SQLite 외부 정렬
  5. 출처 표시별도 파일로 저장
P 문제

연결이 끊긴 구간의 체결은 증권사가 다시 보내 주지 않아 영구히 빠집니다.

A 분석
  • 같은 증권사 재요청: 지나간 체결 수신 불가로 제외
  • 타사 체결 이력 API 사용, 빈 시간대·종목 특정이 선행 조건
  • 원본 보호: 보충분은 출처(vendor, provenance) 붙여 별도 저장
A 실행
  • 감사: 체결 순번 빈틈을 종목별로 계산
  • 보충: 키움 체결 이력·한국투자증권 API로 빈 구간 채움
  • 병합: SQLite 외부 정렬로 합치며 중복 제거
R 결과

감사, 보충, 병합이 독립 CLI 단계. L0 원본 미변경. 당일 체결만 제공하는 등 복구 불가 구간은 남을 수 있음.

CASE 03KRX-Alpha개인

백업 확인된 파일만 삭제, 작은 디스크 대응

P 문제

VPS 디스크는 작은데 틱 원본은 크게 쌓입니다. 보존 기간만 보고 지우면 미업로드 파일도 지웁니다.

A 분석
  • 보존 기간만으로 삭제: 업로드 실패 시 영구 손실이라 제외
  • 원격 전체 목록 조회: 느려 제외, 날짜 접두사별 파일 크기 조회 선택
A 실행
  • 원격(Google Drive)에 같은 크기 파일 존재 + 정규화 완료 파티션만 삭제
  • 여유 공간 3 GB 미만이면 수집 중단(min_free_disk_gb)
R 결과

업로드 미확인 파티션은 보존 기간이 지나도 삭제 제외. 대사 시간 단축 폭은 미측정.

CASE 04KRX-Alpha개인

호가 잔량 반영 모의 체결, 실계좌 오발주 차단

P 문제

현재가 전량 체결 가정은 잔량 부족·슬리피지를 못 봅니다. 같은 코드가 실계좌로 나가면 사고 위험도 있습니다.

A 분석
  • 현재가 즉시 체결: 낙관적이라 제외
  • 10단계 호가를 위에서부터 소진: 현실에 가까워 선택
A 실행
  • 10호가 소진으로 체결가·수량 계산, 지정가는 한도 초과 시 중단
  • 모든 주문이 단일 OMS와 리스크 게이트(주문 금액·분당 주문 수·일 손실 한도·종목 화이트리스트) 통과
  • 실계좌: KRX_ALPHA_EXEC_LIVE_ARMED=true 없으면 설정 단계 오류, 기본값은 모의
R 결과

모의·모의투자·실계좌가 같은 OMS를 쓰고 실계좌만 명시 허용 필요. 실계좌 운용과 모의 체결의 실제 일치 여부는 미검증.

한계

  • 전략(알파) 단계 없음: 신호 생성·백테스트 엔진·수익 수치 없음
  • 틱 손실 0 아님: 복구 불가 구간 가능, 모의 체결 현실성 미검증

구현과 실행 방법은 저장소 README에 있습니다.
