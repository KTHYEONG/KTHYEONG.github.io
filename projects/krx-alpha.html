KRX-Alpha

호가·체결 틱 수집·검증 데이터 파이프라인

개요

호가·체결 틱을 수집하고 누락 구간을 감사·보충해 검증된 백업까지 운영하는 데이터 파이프라인입니다. 증권사 실시간 API는 끊긴 구간의 체결을 다시 보내 주지 않아, 알파(초과수익) 연구에 앞서 수집·감사·보충·백업·모의 주문 처리 인프라를 먼저 만들었습니다. 장 마감 후 감사 기준 수신 손실은 11.5 0.42%, 11.6 0.04%이고, 알파 연구는 시작 전입니다.

사례

CASE 01KRX-Alpha개인

원본 먼저 저장, 해석은 장 마감 후

수신과 해석을 분리했고, 수신 손실은 장 마감 후 세션 감사가 측정합니다(11.5 0.42%, 11.6 0.04%).
  1. 수신실시간 시세 메시지
  2. 원본 기록받은 시각만 붙임
  3. 원본 보관압축 파일에 이어 저장
  4. 장마감 후해석·중복 제거
  5. 정리본 변환열 단위 파일 + 품질 검사
P 문제

개장 직후 시세 메시지가 한꺼번에 몰립니다. 받으면서 내용을 해석하면 처리가 밀려 일부를 놓칠 수 있습니다.

  • 0.04%11.6 손실, 2,612 / 6,127,713건
  • 0.42%11.5 손실, 25,938 / 6,122,358건
  • 2.0%10.29 손실, 89,545 / 4,438,186건, 장 시작 직후 전달 지연 구간 포함
A 분석
  • 받자마자 해석은 단순하나 해석 오류가 곧 데이터 손실이라 제외, 원본 먼저 저장하면 규칙을 고쳐도 다시 계산 가능
A 실행
  • 수신 단계는 받은 시각만 붙여 압축 원본에 이어 저장, 해석·중복 제거·품질 검사는 장 마감 후 따로 처리
R 결과

수신과 해석을 분리했고, 수신 손실은 장 마감 후 세션 감사가 측정합니다(11.5 0.42%, 11.6 0.04%). 손실이 컸던 날은 장 시작 직후 증권사 전달 지연이 있었고(10.20·10.27·10.29, 최대 64초), 이후 야간 보충으로 채웁니다. 운영 기록

CASE 02KRX-Alpha개인

끊긴 구간을 체결 번호로 찾아 보충

감사·보충·병합을 따로 실행하고 원본은 바꾸지 않습니다.
  1. 번호 감사종목별 빈 구간 계산
  2. 구간 확정시간대·종목 특정
  3. 타사 보충키움·한국투자증권 체결 이력
  4. 병합디스크 기반 정렬
  5. 출처 표시별도 파일로 저장
P 문제

실시간 연결이 끊긴 동안의 체결 내역은 증권사가 다시 보내 주지 않아, 그대로 두면 영구히 빠집니다.

A 분석
  • 같은 증권사에 재요청은 지나간 체결을 받을 수 없어 제외, 먼저 빈 시간대·종목을 특정해야 함
  • 원본 보호: 보충분은 출처를 붙여 별도 저장하고, 보충량이 허용 오차(2%)를 넘으면 병합 보류
A 실행
  • 체결 번호가 비는 구간을 종목별로 계산해 키움증권·한국투자증권 체결 이력으로 채우고 중복 제거
  • 10.30·11.2분은 오차 초과로 병합이 보류됐고, 원인이던 감사의 이중 집계를 수정한 뒤 보충 완료
R 결과

감사·보충·병합을 따로 실행하고 원본은 바꾸지 않습니다. 증권사가 당일 체결만 제공하는 구간은 영구히 복구되지 않았고, 날짜별로 운영 점검 문서에 기록했습니다. 운영 기록

  • 1,252건10.20 영구 복구 불가 체결
  • 329건10.22 영구 복구 불가 체결
CASE 03KRX-Alpha개인

백업 확인 후 삭제, 기준은 md5로

수정 배포 전 점검에서 로컬 정리본 1,166개 중 1,155개의 md5가 드라이브와 일치하고 불일치는 0개였습니다(나머지 11개는 주말·당일분 대기).
P 문제

임대 서버의 디스크는 작은데 틱 원본은 계속 쌓입니다. 보존 기간만 보고 지우면 백업 안 된 파일도 지워지고, 크기만 맞춰 보면 손상된 사본으로도 삭제가 승인됩니다.

백업 일치 판정 방식
크기만 비교(수정 전)크기 + md5 비교(현재) 선택
같은 크기의 손상 사본검증 통과, 원본 삭제 승인 가능불일치로 삭제 거부
드라이브 중복 이름감지 못 함동일 사본은 경고, 충돌은 검증 거부
원본 삭제 승인 조건크기 일치크기·md5 일치 + 중복 이름 없음, 확인 못 하면 삭제 안 함
A 실행
  • 업로드·오프로드 검증과 원본 삭제 승인을 모두 크기와 md5 일치 조건으로 변경(2026-11-02 수정)
  • 디스크 여유가 3GB 미만이면 수집 중단
R 결과

수정 배포 전 점검에서 로컬 정리본 1,166개 중 1,155개의 md5가 드라이브와 일치하고 불일치는 0개였습니다(나머지 11개는 주말·당일분 대기). 드라이브 중복 폴더 42개도 병합했습니다. 운영 기록

CASE 04KRX-Alpha개인

호가 잔량 반영 모의 체결과 실계좌 차단

모의·모의투자·실계좌가 같은 주문 처리부를 쓰고, 실계좌는 명시 허용이 있어야만 시작됩니다.
P 문제

현재가에 전량 체결된다고 가정하면 물량 부족과 체결가 밀림을 못 봅니다. 모의용 코드가 실계좌로 나가면 사고 위험도 있습니다.

A 분석
  • 현재가에 즉시 체결은 지나치게 낙관적이라 제외, 10단계 호가를 유리한 쪽부터 소진하는 방식은 현실에 가까워 선택
A 실행
  • 10단계 호가를 소진하며 체결가·수량 계산, 지정가 한도를 넘으면 체결 중단
  • 모든 주문이 하나의 주문 관리 시스템(OMS)과 위험 한도 검사(기본 주문당 100만 원·종목당 300만 원·분당 10건·일 손실 30만 원) 통과
  • 실계좌는 실거래 허용 환경변수를 명시하지 않으면 시작 단계에서 오류, 기본값은 모의
R 결과

모의·모의투자·실계좌가 같은 주문 처리부를 쓰고, 실계좌는 명시 허용이 있어야만 시작됩니다.

한계

  • 전략(알파) 단계 없음: 신호 생성·백테스트 엔진·수익 수치 없음
  • 틱 손실 0 아님: 장 시작 직후 증권사 전달 지연으로 손실이 반복 관측됐고(0.04~2.0%대), 영구 복구 불가 구간(10.20 1,252건 등)이 있음. 원본 먼저 저장이 손실을 줄였는지 비교한 대조 실험은 없음
  • 모의 주문(OMS)은 코드와 테스트로만 확인했고 운영 서버에서 정기 실행하지 않음, 모의 체결 현실성 미검증
