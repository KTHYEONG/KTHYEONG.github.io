데이터를 수집하고 검증하는 시스템을 만들었습니다

끊기거나 겹치거나 틀릴 수 있는 데이터를 믿고 쓸 수 있게 만드는 일을 해 왔습니다. 수집은 원본부터 저장하고 빠진 구간을 채우며, 실행은 기록을 먼저 남겨 재시도해도 중복되지 않게 하고, 분석은 미래 정보와 중복 집계가 섞이지 않게 막았습니다.

    개인진행 중

    장중 시세 수집, 결손 탐지·보충 파이프라인

    • 원본 먼저 저장장중 파싱 없이 수신 시각만 붙여 기록
    • 끊김 자동 보충체결 번호로 빠진 구간을 찾아 채움

    • 끊긴 구간을 체결 번호로 찾아 보충감사·보충·병합을 따로 실행하고 원본은 바꾸지 않습니다.

  1. Emori

    팀완료

    뇌파·감정을 상담 문장으로 바꾸는 모델의 학습 데이터와 파인튜닝

    2025.09 ~ 2025.12 · 뇌파 전처리, 학습 데이터(증강·정답 문장), 모델 파인튜닝 담당. 인터뷰 키워드 분석과 연관 분석 대시보드는 팀원 담당.

    • 70세트학습 입력 (실제 45 + 증강 25, 증강은 기록 1개에서 파생)
    • 210개정답 문장 (280개 중 사용)
    • 168 / 42학습 / 검증 (레코드 단위 분할)

    대표 사례

    • 규칙·범용 LLM 대신 추가학습 선택체험 시작·중간·마지막 3단계를 각각 한 문장으로 서술하는 모델을 만들었습니다.
    • 규칙 증강으로 학습 세트 확장증강 50세트 중 정답 문장이 있는 25세트가 학습 입력 70세트의 일부가 됐고, 모두 실제 기록 1개에서 파생됩니다.

  2. Witches-Chat-Core

    팀완료

    학사 규정을 검색용 Markdown으로 구조화한 RAG 전처리

    2026.03 ~ 2026.06 · 담당: 문서 변환, 구조 표시, 표·양식 분리, 변환 점검. 문서 쪼개기(검색용 조각으로 나누는 단계)·검색·입력 검열·서버 구성은 팀원 담당(변환기 processors.py 952줄 중 543줄이 제 코드, git blame 기준).

    • 3형식 → MarkdownHWP·DOCX·PDF 규정을 하나로 통일
    • 조·항·호 구조 표시계층을 기호로 남겨 문서 쪼개기에 전달
    • 표·양식 분리본문과 구분해서 전달
    • 98.46%악성 질문 차단 (팀 전체, 130개 중 128개)팀 측정

    대표 사례

    • 세 형식을 Markdown 하나로 통일원본 29개 파일에서 Markdown 28개(규정 24종)를 만들어 문서 쪼개기 단계에 전달했습니다.
    • 표와 신청서 양식 분리양식 표가 본문과 분리되어 문서 쪼개기 단계로 전달됩니다.

  3. Port Entity Matching

    개인완료

    규칙으로 못 푸는 한글 선박명을 LLM 후보로 보완한 대회

    2026.10 ~ 2026.11 · 정규화, 후보 검색, 특징, 랭커(후보 순위 모델), 평가 도구, 제출 코드를 단독 설계·구현했습니다.

    • 0.91989 · 106위비공개 리더보드 최종 (468명 중)운영 기록
    • 0.8805 → 0.9595공개 리더보드 점수운영 기록

    대표 사례

    • 한글 선박명, 세 채널로 후보 검색공개 점수가 0.8805에서 0.9595로 올랐습니다.
    • 정체 구간의 중단 판단과 남은 오류 분석한글 정답이 505에서 507로, 점수가 0.9525에서 0.9595로 올랐습니다(후보 폭 확대 0.9563, 학습 선박 제외 0.9581).

AI 활용 방식

AI 코딩 도구를 코드 작성과 처음 접하는 분야 학습에 활용했습니다. 설계와 검증은 직접 맡고, 구현을 AI와 나눴습니다.

  1. 설계직접문제 정의와 비교 기준, 구조를 먼저 정합니다.
  2. 구현AI 도구정한 설계대로 코드를 작성하고, 저는 변경 내용을 검토합니다.
  3. 검증직접테스트와 정적 검사를 통과시키고, 결과 수치는 직접 확인한 것만 씁니다.
